# #11 문서화 이원화: 작업용 결정 기록과 포트폴리오용 진행 기록

- 기간: 2026-11-26
- Issue: [#11](https://github.com/Rasit-NP/curtain-call/issues/11), PR: [#12](https://github.com/Rasit-NP/curtain-call/pull/12)
- 관련 결정: [0024](../decisions/0024-docs-two-tracks.md)

## 배경

사람이 "이 프로젝트를 끝난 뒤 포트폴리오로 쓰려면 문제, 결정, 그리고 판단 근거가 남아야 한다"고 했다. 당시 근거는 Issue·PR 본문, `docs/spec.md` 9장, `docs/agent-log.md`(결함 한 줄), 대화에 흩어져 있었다. 명세 밖의 결정은 저장소 안에서 한곳에 모여 있지 않았고, 대화에서 내린 판단은 사라졌다.

## 판단 과정

1. **에이전트의 첫 제안은 `docs/decisions.md` 파일 하나였다.** 사람이 "결정이 아니라 판단 근거를 남겨야 하고, 수백 개를 문서 하나에 남길 수 있느냐"고 물었다.
2. **두 번째 제안은 판단을 무게별로 나눠 일부만 파일로 남기는 것이었다.** 사람이 "전부 문서화하라"고 했다. 에이전트가 기록할 것을 고르면 근거가 빠진다는 뜻이었다.
3. **사람이 문서의 목적이 둘이라고 정리했다.** 작업 중 에이전트가 결정을 확인하는 문서와, 끝난 뒤 포트폴리오로 정리하는 문서다. 작업만 보면 앞의 것으로 충분하지만 포트폴리오에는 뒤의 것이 필요하다.

## 결정과 근거

[0024](../decisions/0024-docs-two-tracks.md):

- `docs/decisions/`: 결정 하나에 파일 하나. 에이전트가 지금 유효한 결정을 빠르게 찾는다. 바뀌면 새 파일을 만들고 원래 것은 `대체됨`으로 남긴다.
- `docs/history/`: Issue 하나에 파일 하나. 배경, 판단 과정, 실패와 수정, 리뷰, 결과, 배운 점을 시간 순서로 남긴다. 사람이 정한 것과 에이전트가 정한 것을 구분해 적는다.
- 둘 다 PR마다 그때그때 갱신한다. 끝난 뒤 몰아서 쓰면 근거가 사라지기 때문이다.
- 목차와 파일이 어긋나면 `verify.sh harness`가 실패한다(`scripts/check-docs-index.sh`). 판단이 수백 개가 되어도 목차가 믿을 수 있어야 하기 때문이다.

## 결과

지금까지의 결정 25개와 Issue 6건의 진행 기록을 채웠다. 루트 `CLAUDE.md`와 PR 템플릿에 갱신 규칙을 넣었다. 사람이 PR [#12](https://github.com/Rasit-NP/curtain-call/pull/12)를 main에 병합했다(병합 커밋 `e7c32d5`).

## 배운 점

- 에이전트가 "중요한 것만" 고르면, 무엇이 중요했는지는 나중에야 알 수 있다. 기록은 고르지 않고 남기고, 찾기 쉽게 만드는 쪽으로 풀어야 한다.
