## 배경

로드맵 [#13](https://github.com/Rasit-NP/curtain-call/issues/13)의 6단계(마무리) 첫 항목이다. 백엔드(결제·멱등 키 #55·#56)와 프론트엔드(결제 화면 #52)가 모두 병합돼,
실제 브라우저·백엔드·DB로 처음부터 끝까지 도는 E2E를 처음 만든다.

- `e2e/`에는 `CLAUDE.md`만 있다. `e2e/package.json`이 생기면 `verify.sh`(전체)와 `verify.sh e2e`가 E2E를 돌린다.
- 백엔드 보안 설정은 `e2e` 프로필에서 `POST /api/test-support/reset`을 토큰 없이 열어 두었고, 컨트롤러는 없다.
- 시드(계정·공연장·공연·좌석)는 `db/seed`의 Flyway 마이그레이션(`V1000__`~)으로 `local`·`e2e`에서만 들어가고, 두 프로필은 같은 DB를 쓴다.
- 같은 6단계의 #61(정리)은 다른 세션에서 동시에 진행한다. 이 세션은 결정 번호를 0160부터 쓴다.

## 판단과 근거(에이전트)

- **초기화**(결정 0160): Flyway 이력을 뺀 모든 테이블을 한 트랜잭션에서 `TRUNCATE ... RESTART IDENTITY CASCADE`하고 시드 파일을 다시 실행한다.
  시드 테이블까지 비워 바뀐 시드 값과 더해진 행이 남지 않게 했고, 테이블 목록은 DB에서 읽어 새 테이블도 빠지지 않게 했다.
  Flyway `clean`+`migrate`는 스키마를 지웠다 다시 만들어 느리고 `clean`을 켜야 해서 고르지 않았다.
- **임시 DB를 띄우는 방법**(결정 0162): 통합 테스트처럼 Testcontainers를 쓰되, 테스트 소스와 따로 둔 소스 세트(`src/e2eRun`)의 실행기로 띄운다.
  Spring Boot가 권하는 `bootTestRun`(테스트 클래스패스)은 테스트 소스의 시험용 컨트롤러 4개와 `IntegrationTestConfig`(고정 시계)가 컴포넌트 스캔에 걸려 E2E 서버에 들어가므로 쓰지 않았다.
  compose의 E2E 전용 서비스와 셸 스크립트는 프로세스가 강제로 끝나면 컨테이너가 남고, `npx playwright test`만으로는 돌지 않아 고르지 않았다.
- **빈 포트**(결정 0162): 설정 파일이 고른 포트를 환경변수로 작업자 프로세스와 나눈다. Playwright는 `webServer`를 `globalSetup`보다 먼저 띄우므로(설치된 Playwright 소스로 확인)
  `globalSetup`에서는 고를 수 없다.
- **E2E 테스트 작성**(결정 0163): 공연·좌석은 API로 찾고 화면에서는 목록 위치로 고른다(시드에 제목이 같은 회차가 있다). 로그인은 화면으로 하고,
  헤더와 이름이 겹치는 링크는 화면 영역(화면 제목이 이름인 region)으로 좁힌다. 시나리오 2는 빈 좌석을 함께 골라 '묶음이 하나도 잡히지 않음'까지 보고,
  시나리오 4는 로그인 뒤 원래 화면으로 돌아오는 것까지 본다.
- **verify.sh e2e**: 개발 DB를 띄우던 단계를 빼고 Docker 확인, 프론트엔드 의존성, 타입 검사를 더했다.
  프론트엔드 의존성 단계는 이 워크트리에 `frontend/node_modules`가 없어서 넣었다. E2E가 프론트엔드 개발 서버를 띄우는데, `verify.sh e2e`만 돌리면 설치하는 단계가 없었다.

## 실패와 수정

- **하네스 실패(문서 목차)**: 결정 0161 파일을 만들고 목차에 넣기 전에 `verify.sh harness`를 돌려 '목차에 없는 파일'로 실패했다. 목차에 행을 더해 통과시켰다.
- **E2E가 찾은 결함**: 없다. 시나리오 4개가 처음 실행에서 통과했고, 실행 중 백엔드 로그의 경고·오류와 브라우저의 잡히지 않은 예외가 없었다. 그래서 `docs/agent-log.md`에 더한 줄은 없다.

## 배운 점

- 워크트리에서 '로컬 개발과 같은 설정'을 그대로 쓰면, 사람이 띄운 서버와 DB를 시험하거나 지우게 된다. 환경을 함께 쓰는지는 구현 전에 사람에게 물을 정책이었다.
- 서버를 띄우는 E2E는 테스트가 통과해도 뒤에 프로세스·컨테이너가 남을 수 있다. 강제 종료까지 직접 해 보고 무엇이 남는지 확인해야 실행을 되풀이해도 쌓이지 않는다.
