# #47 프론트엔드 좌석 선택 화면 테스트 보강(R2): 좌석을 고르면 안내 문구를 지운다

- 기간: 2026-11-27 ~
- Issue: [#47](https://github.com/Rasit-NP/curtain-call/issues/47), PR: (작성 중)
- 관련 결정: [0110](../decisions/0110-seat-notice-clear-on-select-test.md)

## 배경

로드맵 [#13](https://github.com/Rasit-NP/curtain-call/issues/13)의 '3단계 뒤 점검 수정' 단계다. 3단계(선점)가 병합된 뒤 메인 세션이 프로젝트를 점검하며 찾은 테스트 공백이다.
명세 7.2(결정 0081)는 안내 문구를 다음 행동(좌석을 고르거나 취소, '좌석 선택 완료')을 하면 지운다고 정했다.
그런데 이를 검증한다는 테스트는 4석을 고른 상태에서 5번째 좌석으로 문구를 띄워, '취소'로 지우는 경로만 지났다.
점검 에이전트가 좌석을 고를 때의 `setNotice(null)`을 지운 변형으로 돌렸더니 기존 프론트엔드 테스트 157개가 모두 통과했다.
구현은 명세대로 동작하므로 테스트만 보강한다. 백엔드(#45)와 문서(#46) 점검 Issue가 다른 세션에서 동시에 진행된다.

## 진행

- 메인 세션이 이 Issue용 워크트리 세션을 시작했다. 브랜치를 `test/47-seat-notice-clear`로 바꾸고, 시작점이 최신 `origin/main`(`212e3b4`)인지 확인했다.
- Issue에 '아직 정하지 않은 정책'이 없고, 테스트 방법은 '에이전트가 정하는 것'으로 맡겨져 있어 사람에게 묻지 않았다.

## 판단과 근거(에이전트)

- **문구를 띄우는 방법**: 5번째 좌석으로 띄우면 이미 4석이라 좌석을 더 고를 수 없다. 문구가 뜬 채 좌석을 고를 수 있는 것은 선점 요청이 실패해 4석 미만이 남을 때뿐이라, 2석으로 선점 요청을 보내 `409 HOLD_LIMIT_EXCEEDED`를 받게 했다. 이미 가진 좌석 때문에 실패한 사용자가 다시 고르는 실제 흐름이고, `SEAT_ALREADY_HELD`는 고른 좌석을 비워 맞지 않는다.
- **새 테스트를 더하고 기존 이름을 고침**: 기존 테스트는 검증 내용을 그대로 두고 이름만 실제 경로('취소')대로 바꿨다. 이름이 '고르거나'를 말해 대응표만 보면 검증된 것으로 읽혔던 것이 이번 공백을 가린 원인이었다(결정 0110).
- **기다림**: 선점 요청이 끝날 때까지 좌석이 막혀 있으므로, 문구가 뜬 뒤 좌석이 다시 눌릴 수 있을 때까지 기다리고 누른다.

## 실패와 수정

- 되돌림 확인: `SeatSelectPage.tsx` 84줄(좌석을 고를 때의 `setNotice(null)`)을 지우고 좌석 선택 화면 테스트를 돌리자 새 테스트만 실패했다(32개 중 1개). 복구한 뒤 모두 통과했다.
