## R6 되돌림 확인

운영 코드의 한 부분을 잠시 바꾸고 테스트를 돌린 뒤 `git checkout`으로 되돌렸다. 시작 전에 모든 변경을 커밋해 두었고, 매번 `git status`로 운영 코드가 커밋과 같은지 확인했다.
'PR #38의 내 예매 요청에는 토큰을 Bearer로 붙인다'는 PR #38 병합 커밋(`087b22a`)에도 `reservations.test.ts`의 'R6: GET /api/reservations에 저장된 토큰을 Bearer로 붙여 …' 하나뿐이어서, 리뷰가 이 테스트를 줄여 부른 것으로 보았다.

| 되돌림 | 결과 |
|---|---|
| 1. 공연 목록(`/`)을 `routes.tsx`의 가드 아래로 옮김 | 'R6: 로그인하지 않아도 공연 목록을 볼 수 있다'가 실패(`Unable to find role="heading" and name "작은 방의 햄릿"`). 공연 목록·헤더·로그아웃 테스트 등 모두 14개 실패 |
| 2. 공연 목록 API 함수를 `auth: true`로 바꿈(3번 실행) | 3번 모두 R6 테스트 2개('저장된 토큰이 있어도 … 붙이지 않는다', API 함수와 화면)만 실패. 내 예매 `AUTH_REQUIRED` 테스트는 3번 모두 통과 |
| 3. 내 예매 API 함수를 `auth: false`로 바꿈 | Bearer 테스트가 실패(`expected null to be 'Bearer token-1'`). 내 예매 화면 테스트 등 모두 6개 실패 |
| 4. API 클라이언트가 `Bearer ` 없이 토큰만 붙임 | Bearer 테스트가 실패(`expected 'token-1' to be 'Bearer token-1'`). 다른 API의 Bearer 테스트 등 모두 9개 실패 |
| 5. `handleAuthRequired`가 토큰을 지우지 않음 | 헤더의 `AUTH_REQUIRED` 테스트 2개 모두 실패 |
| 6. `clearAccessToken`이 변경을 알리지 않음 | 헤더의 '로그인 화면에 있어 화면 이동이 없어도, …' 1개 실패 |

- **'로그인하지 않아도 공연 목록을 볼 수 있다'는 되돌림 2에서 통과한다.** 결함이 아니라고 보았다. 토큰이 없으면 `auth: true`여도 헤더 없이 보내므로(클라이언트 테스트 'R6: 인증이 필요한 요청이라도 저장된 토큰이 없으면 헤더 없이 보낸다'),
  로그인하지 않은 사용자가 겪는 동작은 바뀌지 않는다. 되돌림 2가 깨는 것은 '저장된 토큰이 낡았을 때'이고, 그것은 같은 파일의 R6 테스트가 잡는다.
- **헤더의 첫 테스트는 되돌림 6에서 통과한다.** 내 예매에서 로그인 화면으로 옮겨 가며 헤더가 다시 그려지기 때문이다. 화면 이동이 없는 경우를 둘째 테스트가 맡도록 짝지어 둔 것이라 보강하지 않았다.
- 되돌림 2는 0036의 기록을 확인하려고 돌렸다. 0036이 '공연 목록 함수를 `auth: true`로 바꾸면 … 내 예매 `AUTH_REQUIRED` 테스트가 실패했다'고 적은 것은 같은 문서 바로 위 항목의 불안정한 테스트(#36에서 고침) 때문이었고,
  지금 코드에서는 그 테스트가 3번 모두 통과했다. 0036에 이렇게 바로잡았고, 원래 문장이 무엇이었는지도 남겼다.
- 테스트를 보강하지 않았으므로 기대값도, 테스트 코드도 바꾸지 않았다. 바꾼 테스트 코드는 헤더 테스트 이름 2개뿐이다.

## 판단과 근거(에이전트)

- **헤더 테스트를 대응표의 R6 절로 옮겼다.** 대응표의 '규칙 밖 명세 동작' 절은 '테스트 이름에 규칙 번호를 붙이지 않는다'고 적혀 있다. 그 절의 '로그인하거나 `AUTH_REQUIRED`로 토큰이 지워지면 헤더가 바로 바뀐다' 행을
  '로그인하면 헤더가 바로 로그아웃으로 바뀐다'(규칙 밖에 남김)와 R6 행('`AUTH_REQUIRED`로 토큰이 지워지면 헤더가 바로 로그인으로 바뀐다(로그인 화면에 있어 화면 이동이 없어도)')으로 나눴다.
  #52가 `AUTH_REQUIRED` 문구 감추기 테스트 3개에 `R6:`을 붙일 때 R6 행으로 옮긴 것과 같다.
- **결함 기록(`docs/agent-log.md`)에 더하지 않았다.** 되돌림 확인에서 테스트 결함이 나오지 않았다. 0036의 잘못 적은 기록은 PR #38 리뷰가 이미 찾은 것이고, 진행 기록 정정(#39·#46)도 결함 기록에 올리지 않았다.
- **결정 기록을 만들지 않았다.** 진행 기록 문장과 테스트 이름만 바꿨고, 결정 파일의 상태는 Issue대로 그대로 두었다.
