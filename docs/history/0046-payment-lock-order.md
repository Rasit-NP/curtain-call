## 배경

로드맵 [#13](https://github.com/Rasit-NP/curtain-call/issues/13)의 3단계(선점)가 병합된 뒤, 메인 세션이 프로젝트를 점검했다(2026-11-27).
`./scripts/verify.sh` 전체가 통과했고 실제 앱 연동도 정상이었지만, 코드와 결정을 읽다가 고칠 것을 찾았다. 사람이 이를 Issue #45(백엔드), #46(문서), #47(프론트엔드 테스트)로 등록했고,
4단계 전에 세 Issue를 동시에 진행한다. 이 Issue는 문서만 고친다.

찾은 것은 두 가지다.

1. **결정 0073의 R2 보장 주장이 결제에는 틀렸다.** 0073은 "사용자 행 잠금은 같은 사용자의 해제·결제와는 한 줄로 세우지 않아도 4석을 넘기지 않는다"고 했다.
   해제에는 맞지만 결제에는 맞지 않는다.
   - 사용자 U가 2석 선점 H를 만료 1초 전에 결제한다. 결제는 좌석을 잠그고 만료 판정을 통과한 뒤, 모의 결제가 늦게 끝난다(명세 2.4의 R4가 허용).
   - 만료 시각이 지난 뒤 U가 같은 공연의 다른 4석을 선점한다. 결제가 사용자 행을 잠그지 않으므로 이 요청은 기다리지 않는다.
   - 이 요청이 보기에 H는 만료라 세지 않고, 결제가 만든 예매는 커밋 전이라 보이지 않는다(READ COMMITTED). 0 + 4석으로 한도를 통과한다.
   - 결제가 커밋되면 예매 2석 + 유효한 선점 4석 = 6석이 된다(R2 위반).
   - 5단계에서 선점 생성이 선점 좌석과 예매 좌석을 두 문장으로 읽으면, 그 사이에 결제가 커밋될 때 같은 좌석을 양쪽에서 모두 빼고 셀 수도 있다.
   - 지금 코드(선점 생성만 있음)의 결함은 아니다. 결제 코드가 없어 재현하지 않았고, 5단계에서 대응표 행으로 재현·검증한다.
2. **진행 기록이 병합 뒤에 갱신되지 않았다.** #39에서 한 번 고친 문제가 다시 생겼다. 목차에서 #39·#41·#42가 병합됐는데 '진행 중'이었고,
   0039·0042의 '기간'이 열려 있었으며, 0039에는 PR 링크가 없고 '결과'에 병합 전 문장이 남아 있었다.

## 판단과 근거(에이전트)

Issue의 '에이전트가 정하는 것'(결제의 잠금 순서, 교착 상태가 생기지 않는 근거, 해제의 사용자 행 잠금 여부)이다. 모두 [0100](../decisions/0100-hold-concurrency-v2.md)에 적었다.

- **잠금 순서는 하나다: 사용자 행 → 선점 행 → 좌석(`id` 오름차순).** 선점 생성은 사용자 행 → 좌석, 결제는 요청한 사용자 행 → 선점 행 → 좌석, 해제는 선점 행 → 좌석이다.
  모든 요청이 이 순서로만 잠그므로, 잠금을 기다리는 요청은 그보다 앞 순서의 잠금만 쥐고 있고 기다림이 원을 이룰 수 없다.
- **결제가 사용자 행을 잠가야 하는 이유.** 보유 좌석 수를 늘리는 요청은 선점 생성뿐이지만, 결제는 선점 생성이 세지 않는 것(만료된 선점)을 세는 것(예매)으로 바꿀 수 있다.
  판정을 통과한 결제는 만료 시각을 넘겨 커밋될 수 있기 때문이다. 그래서 같은 사용자의 결제와 선점 생성은 한 줄로 서야 한다.
  한 줄로 서면 선점 생성이 먼저일 때 결제는 그 뒤에 현재 시각을 읽어 같은 만료 판정을 하고, 결제가 먼저일 때 선점 생성은 커밋된 예매를 읽는다.
- **사용자 행을 가장 먼저 잠근다.** 선점 행 → 사용자 행 → 좌석도 순환은 없지만, 사용자 행을 기다리는 동안 다른 잠금을 쥐지 않게 하고 선점 생성과 같은 규칙으로 두려고 맨 앞에 뒀다.
  사용자 행을 좌석 뒤에 잠그면 같은 사용자의 선점 생성과 교착 상태가 생기고, 만료 판정 뒤에 잠그면 R2를 지키지 못한다(0100에 경우를 적었다).
  그래서 명세 2.4의 R4에도 "좌석을 잠근 뒤 현재 시각을 읽어 만료를 판정"한다고 시각을 읽는 때를 적었다.
- **해제는 사용자 행을 잠그지 않는다.** 해제는 보유 좌석 수를 줄이기만 한다. 선점 생성은 선점을 한 문장으로 읽어 해제 전이나 뒤 중 하나를 보고, 예매는 해제가 바꾸지 않는다.
  한 줄로 세워도 어느 쪽이 먼저인지는 도착 순서에 달려 결과가 달라지지 않고 기다림만 는다.
- **명세에는 결과와 잠금 순서만 적었다.** 2.4의 R2 결과에 결제와 선점 요청이 동시에 올 때를 더하고, 결제·해제의 잠금 문장을 요청별 잠금 순서 표로 바꿨다. 근거는 결정 0100에 두고 명세에서 링크했다.
- **0073 본문은 고치지 않았다.** 상태만 `대체됨(→0100)`으로 바꿨다(루트 `CLAUDE.md` '문서화' 3번). 0100은 0073의 선점 생성 결정을 그대로 옮기고 결제·해제를 더했다.
- **대응표**: R2 표에 5단계 동시성 행을 `미작성`으로 더하고, 결제의 사용자 행 잠금을 빼면 그 테스트가 실패해야 한다고 표 아래에 적었다.
- **진행 기록 정정**: 병합 시점은 #39처럼 병합 커밋으로 적었다(PR #40 → `77e4bdf`, PR #43 → `a28127c`, PR #44 → `212e3b4`, `git log origin/main`으로 확인).
  세 PR 모두 한국 시간 2026-11-27에 병합돼 '기간'의 끝 날짜는 2026-11-27이다.
