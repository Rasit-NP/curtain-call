# #3 명세와 규칙-테스트 대응표 작성

- 기간: 2026-11-26
- Issue: [#3](https://github.com/Rasit-NP/curtain-call/issues/3), PR: [#4](https://github.com/Rasit-NP/curtain-call/pull/4) (병합)
- 관련 결정: [0003](../decisions/0003-hold-is-seat-bundle.md)~[0009](../decisions/0009-seat-hold-id.md)
- 산출물: [`docs/spec.md`](../spec.md), [`docs/test-matrix.md`](../test-matrix.md)

## 배경

규칙(R1~R6)과 오류 코드 표만으로는 백엔드·프론트엔드·E2E가 같은 가정을 하고 만들 수 없었다. 다음이 정해지지 않았다.

1. 선점 1건이 좌석 하나인지 묶음인지
2. 선점 해제 API가 있는지
3. 결제 실패 뒤 같은 멱등 키 재요청, 선점 유지, 같은 키에 다른 본문, 결제 실패를 알릴 오류 코드
4. 엔드포인트 경로와 요청·응답 형태

루트 `CLAUDE.md`는 "규칙이 모호하면 구현하지 말고 사람에게 넘긴다"고 한다. 그래서 문서를 쓰기 전에 사람이 정하게 했다.

## 판단과 근거

**사람이 정한 것**(근거는 각 결정 파일과 `docs/spec.md` 9장)

- 선점은 좌석 묶음([0003](../decisions/0003-hold-is-seat-bundle.md)): CGV 예매 방식.
- 다른 화면으로 가면 해제, 창을 닫으면 만료까지 유지([0004](../decisions/0004-hold-release.md)): 사람이 CGV에서 직접 확인한 동작.
- 결제 거절은 `402 PAYMENT_FAILED`([0005](../decisions/0005-payment-failed-402.md)).
- 같은 키에 다른 선점이면 `400`([0006](../decisions/0006-idempotency-record.md)).
- 평면 API([0007](../decisions/0007-flat-api.md)).
- 프론트의 401 처리는 `AUTH_REQUIRED`에만([0008](../decisions/0008-auth-required-only.md)).

**에이전트가 정하고 리뷰에서 확인받은 것**

- 오류 검사 순서, 응답 필드 이름, 화면 경로와 문구.
- 멱등 키 1~100자와 사용자별 구분.
- 같은 키 동시 요청은 기다렸다가 같은 결과를 준다. IETF 초안은 409를 권하지만 R5의 '같은 결과'를 지키려고 이렇게 정했다.
- 405·415는 `400 INVALID_INPUT`으로 응답한다.
- JWT 허용 오차는 0이다.

## 독립 리뷰로 찾은 명세 결함

명세를 쓰지 않은 서브에이전트가 두 문서를 `CLAUDE.md` 4개와 대조해 12건을 지적했다. 원문과 맞춰 보니 모두 맞아 전부 반영했다. 그중 주요 결함은 다음과 같다([`docs/agent-log.md`](../agent-log.md)).

- **R5 위반**: 결제 검사 순서가 '저장된 응답 확인 → 선점 확인'이면 같은 키 동시 요청이 404를 받는다. 같은 키를 먼저 잡고 기다리도록 바꿨다.
- **결정끼리 충돌**: 404·409를 저장하지 않으면 '같은 키, 다른 선점은 400'과 어긋난다. 검증을 통과한 결과를 모두 저장하도록 바꿨다.
- **테스트가 결함을 잡지 못함**: R1 교착 상태 테스트가 겹치는 좌석 하나뿐인 묶음이라 정렬을 되돌려도 실패하지 않았다. 같은 두 좌석을 반대 순서로 담아 여러 번 반복하는 테스트로 바꿨다.
- **판정 기준 부재**: 좌석을 잡은 선점을 가리키는 값이 없었다. `Seat.holdId`를 추가했다([0009](../decisions/0009-seat-hold-id.md)).

## 질문 중 정정

결정을 물을 때 "Stripe는 파라미터가 다른 키 재사용을 400으로 거부한다"고 설명했다. 다시 확인해 보니 HTTP 상태까지는 확인되지 않았다. 사용자에게 알렸고, 결정 기록에는 확인된 내용만 남겼다.

## 결과

`docs/spec.md`(도메인, API 10개, 화면)와 `docs/test-matrix.md`(R1~R6마다 정상·실패·경계 테스트와 계층, 모두 미작성)를 썼다. 오류 코드 표에 `402 PAYMENT_FAILED`를 추가했다.

## 배운 점

- 규칙이 짧을수록 구현 전에 정할 것이 많다. 모호한 것을 먼저 사람에게 물어 문서로 고정하면, 영역별 작업을 나눠 맡길 수 있다.
- 쓴 사람이 아닌 리뷰어가 원문과 대조하는 리뷰가 명세 결함을 가장 많이 찾았다.
