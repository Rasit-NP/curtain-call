# 0062. 프론트: 화면 제목·항목 배치, 로딩·빈 목록 문구는 role="status"이고 오류 문구만 role="alert"

- 상태: 에이전트 결정
- 날짜: 2026-11-27
- 결정한 사람: 에이전트. 2026-11-27 Issue #36 세션에서 사람에게 물었고, 사람이 "잘 모르겠음. 중요한 내용이 아니면 추천대로 진행"이라고 맡겨 에이전트가 중요하지 않다고 보고 추천대로 했다. 사람이 이 내용을 확인하지는 않았다.
- 관련: Issue [#36](https://github.com/Rasit-NP/curtain-call/issues/36), 명세 7.4·7.5·7.7

## 결정

- 화면 제목(`h1`)은 '공연 목록', '내 예매'다. 항목마다 공연 제목은 `h2`다.
- 공연 목록 항목: 제목, 일시, 장소, 가격을 한 줄씩. 항목 전체가 링크다.
- 내 예매 항목: 제목, `일시 · 장소`, `좌석 A-1, A-2`, `금액 60,000원`을 한 줄씩.
- 로딩('불러오는 중입니다.')과 빈 목록 문구는 `role="status"`, 오류 안내 문구(명세 7.6)만 `role="alert"`다. 내 예매의 빈 목록 '공연 목록' 링크는 상태 문구 밖에 둔다.

## 근거

- Issue의 "안내 문구는 `role="alert"` 영역에 둔다"가 로딩·빈 목록 문구까지 뜻하는지 모호했다. 명세 7.6의 '안내 문구'는 code별 오류 문구다.
- `alert`는 화면 읽기 프로그램이 하던 말을 끊고 바로 읽는다. 로딩·빈 목록은 그럴 만큼 급한 정보가 아니라 `status`가 맞다.
- 중요하지 않다고 본 이유: 사용자가 보는 글과 흐름은 같고, 화면 읽기 프로그램이 읽는 방식과 테스트가 찾는 역할만 다르다. 나중에 바꾸려면 `LoadStatus`와 빈 목록 한 줄씩, 테스트의 역할 이름만 고치면 된다.

## 고려했지만 고르지 않은 것

- 로딩·빈 목록 문구도 `role="alert"`: Issue 문장을 가장 넓게 읽은 것이다. 위 이유로 고르지 않았다.

## 적용과 남은 점

- 명세 7.5에 '로딩·빈 목록 문구는 `role="status"`'를 더했다. E2E도 이 역할로 찾는다.
- 사람이 확인하면 `채택`으로 바꾼다.
