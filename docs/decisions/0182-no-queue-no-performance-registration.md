# 0182. 대기열과 공연 등록은 만들지 않는다. 공연 등록을 범위 밖 목록에 더한다

- 상태: 채택
- 날짜: 2026-11-28
- 결정한 사람: 에이전트가 추천하고, 사람이 로드맵 2를 승인해 확정(2026-11-28 메인 세션)
- 관련: 로드맵 2 [#64](https://github.com/Rasit-NP/curtain-call/issues/64), Issue [#65](https://github.com/Rasit-NP/curtain-call/issues/65), 결정 [0180](0180-roadmap2-transition.md), spec 2.4, 2.5, 8장

## 결정

- 대기열은 만들지 않는다. 범위 밖 목록에 그대로 둔다.
- 공연 등록은 만들지 않는다. 루트 `CLAUDE.md` '금지 사항'과 명세 8장의 범위 밖 목록에 더한다. 공연과 좌석은 지금처럼 시드로 만든다.
- 범위 밖 목록의 나머지(Redis, Kafka, 실제 PG 연동, 관리자 화면)는 그대로 둔다.
- 근거를 명세 8장에 적고, 루트 `CLAUDE.md`는 8장을 가리킨다.

## 근거

- 대기열: 서버 과부하 대책이지 정확성 문제가 아니다. 같은 좌석은 한 명만 잡는다는 R1은 DB 잠금으로 이미 보장한다(spec 2.4). 제대로 만들려면 Redis가 필요하다.
- 공연 등록: 관리자 역할과 권한이 필요하고, 핵심 규칙(R1~R6)과 거리가 멀다.
- 범위 밖 목록에 이유가 없으면 다음 로드맵을 정할 때 같은 검토를 다시 한다.

## 고려했지만 고르지 않은 것

이유는 위 근거에서 #65 세션의 에이전트가 정리했다.

- 대기열을 선택 단계로 넣기: 위 근거대로 Redis가 필요하고 정확성 규칙을 더하지 않는다. 부하는 k6 부하 테스트(4단계)로 잰다.
- 공연 등록을 관리자 화면 없이 API로만 넣기: 그래도 관리자 역할과 권한을 정해야 한다.
