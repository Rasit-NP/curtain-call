# 0061. 프론트: 헤더 로그인 뒤에는 보던 화면으로, 로그인 화면에도 헤더, 로그아웃 뒤 안내 문구 없음

- 상태: 채택
- 날짜: 2026-11-27
- 결정한 사람: 사람(2026-11-27 Issue #36 세션에서 선택지 중 고름)
- 관련: Issue [#36](https://github.com/Rasit-NP/curtain-call/issues/36) '아직 정하지 않은 정책', 결정 [0041](0041-frontend-login-return-path.md), 명세 7.8

## 결정

- 헤더의 '로그인'을 눌러 로그인하면 보던 화면(경로·쿼리·해시)으로 돌아간다. 가드와 같은 방식으로 location state의 `from`에 지금 경로를 넘긴다(0041).
- 로그인 화면에도 헤더를 보여 준다. '로그인' 링크는 지금 화면 표시(`aria-current="page"`)를 하고, 눌러도 가드나 `AUTH_REQUIRED` 처리가 넘긴 돌아갈 화면을 잃지 않는다.
- 로그아웃한 뒤 안내 문구를 보여 주지 않는다.

## 근거

에이전트가 선택지와 추천을 보이고 사람이 추천을 골랐다. 추천 근거:

- 보던 화면: 가드로 들어온 경우와 동작이 같고, 이미 있는 돌아갈 경로 처리(0041)를 그대로 쓴다. 지금은 로그인 전에 헤더가 보이는 화면이 공연 목록과 로그인 화면뿐이라 차이가 작고, 앞으로 공개 화면이 생기면 차이가 난다.
- 로그인 화면의 헤더: 모든 화면의 헤더가 같고, '커튼콜'로 공연 목록에 돌아갈 길이 생긴다.
- 로그아웃 안내 없음: 헤더가 바로 '로그인'으로 바뀌는 것으로 충분하고, 명세 7.6에 없는 문구와 지울 시점을 새로 정하지 않아도 된다.

## 고려했지만 고르지 않은 것

- 헤더 로그인 뒤 항상 공연 목록으로: 가장 단순하지만 가드로 들어온 경우와 동작이 다르다.
- 로그인 화면에서 '로그인' 링크만 빼기, 로그인 화면에 헤더 없음: 화면마다 헤더 모양이 달라지거나, 공연 목록으로 돌아가려면 뒤로가기를 써야 한다.
- 로그아웃 뒤 공연 목록에 '로그아웃했습니다.': 새 문구와 지울 시점을 정해야 한다.

## 적용과 남은 점

- `Header`는 로그인 화면이 아니면 `loginRedirectState(location)`을, 로그인 화면이면 지금 location state를 그대로 링크에 넘긴다. 로그인 화면인지는 `matchPath(LOGIN_PATH, pathname)`으로 판단한다(0043과 같은 규칙).
