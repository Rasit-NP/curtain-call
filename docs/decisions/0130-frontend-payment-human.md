# 0130. 프론트: 결제 화면 — 시계 없이 만료는 서버만 판단, 만료면 결제 버튼을 남기고 막음, 제한 안내 문구, '뒤로 가기' 버튼

- 상태: 채택
- 날짜: 2026-11-28
- 결정한 사람: 사람(2026-11-27~28 Issue #52 세션에서 에이전트가 물은 정책에 직접 답하거나 선택지를 골랐다)
- 관련: Issue [#52](https://github.com/Rasit-NP/curtain-call/issues/52), 명세 7.3, 결정 [0131](0131-frontend-payment-recommended.md)

## 결정

사람이 자기 말로 정했거나 선택지에서 고른 것만 적는다. "추천대로" 맡긴 것은 [0131](0131-frontend-payment-recommended.md)에 있다.

- **남은 시간(시계)을 보여 주지 않는다. 만료는 서버만 판단한다**: 결제 화면은 시간을 세지 않는다. 들어올 때 선점이 `EXPIRED`이거나 결제 응답이 `409 HOLD_EXPIRED`일 때만 시간이 지났다고 보여 준다.
  - 처음 물을 때 3번(남은 시간이 0이 되면)에 사람이 답했다: "프론트에서 보여주는 시계가 서버와 동일하란 보장이 없지 않나요? 결제 버튼은 남겨두되, 결제가 불가능하도록 처리합니다. 이 때, 시간이 초과되었다는 메시지를 보여줍니다."
  - 에이전트가 서버가 만료를 알려 준 경우의 버튼과 0초 화면의 시계 줄을 다시 묻자 사람이 답했다: "굳이 시계를 보여줘야 하나요? 걍 보여주지 말죠. 제한 시간 안에 결제해야 한다는 문구 정도면 충분하지 않을까요?", "화면 시계 걍 빼죠".
  - 에이전트가 시간이 다 된 것을 누가 판단할지 물었고(서버만 / 보이지 않게 셈), 사람이 '서버만 판단'(추천)을 골랐다.
- **만료가 확인되면 결제 버튼을 남기고 누를 수 없게 한다**: 선점이 `EXPIRED`로 오거나 결제 응답이 `409 HOLD_EXPIRED`면 `HOLD_EXPIRED` 안내 문구('좌석 선점 시간(5분)이 지났습니다. 좌석을 다시 선택해 주세요.')를 보여 주고 '결제하기'를 누를 수 없게 한다.
  선택지(남기고 누를 수 없게 / 버튼을 두지 않음) 중 사람이 '남기고 누를 수 없게'(추천, 사람의 3번 답과 같은 모양)를 골랐다. 그때까지 명세 7.3은 'EXPIRED면 결제 버튼을 두지 않는다'였다.
- **제한 시간 안내**: 결제 전에는 결제 버튼 위에 '선택한 좌석은 5분 동안 잡아 둡니다. 5분 안에 결제해 주세요.'를 평범한 글씨(알림 아님)로 보여 준다. 선택지(시간 없는 문장 / 마감 시각을 씀) 중 사람이 '시간 없는 문장'(추천)을 골랐다.
- **'좌석 다시 선택' 대신 '뒤로 가기'**: 사람의 답: "'다시 선택'이라고 명시되어 있는 버튼은 없습니다. 결제 화면에서 '뒤로 가기' 혹은 '취소' 형태로 보이게 만듭니다."
  에이전트가 이름(뒤로 가기 / 취소)을 묻고 '결제 전(만료·402 뒤 포함)에는 늘 결제하기 옆에 두고, 누르면 선점을 해제한 뒤 그 공연의 좌석 선택 화면으로 돌아간다(브라우저 뒤로가기와 같은 결과). 명세의 '좌석 다시 선택' 링크도 이 버튼으로 바꾼다'고 설명했다. 사람이 '뒤로 가기'(추천)를 골랐다.

## 근거

- 사람이 정했다. 기기 시계는 서버 시계와 같다는 보장이 없어(사람의 지적), 화면이 세는 시간으로 버튼을 막으면 유효한 선점인데 막히거나 그 반대가 될 수 있다. 서버 판정(명세 2.2, R3·R4)만 따르면 이런 어긋남이 없다.
- 에이전트가 물을 때 든 근거는 [docs/history/0052](../history/0052-frontend-payment.md)의 '정책 결정(사람)'에 있다.

## 고려했지만 고르지 않은 것

- 남은 시간 `4분 59초`를 1초마다 보여 주고 0이 되면 버튼을 막음(그때까지 Issue·명세의 정책), 시계를 감추고 화면이 만료 시각에 버튼을 막음.
- 남은 시간의 기준을 응답의 `Date` 헤더(서버 시각)로 보정함(처음 4번 추천). 시계를 빼면서 필요 없어졌다.
- 만료가 확인되면 결제 버튼을 지움(그때까지 명세 7.3, 처음 3·14번 추천).
- 마감 시각을 쓴 문구(`19:05까지 결제해 주세요.`).
- 버튼 이름 '취소': 만료된 뒤에는 취소할 것이 없고, 만들지 않는 '예매 취소'(명세 8장)로 읽힐 수 있다. 이름 '좌석 다시 선택'(그때까지 명세).

## 적용과 남은 점

- 명세 7.3과 테스트 대응표 R3 프론트 행을 바꿨다. Issue 완료 조건의 '남은 시간이 0이 되면 결제 버튼을 막는다(가짜 타이머로 1초 전과 0이 되는 순간)'는 이 결정으로 '기기 시계가 만료 시각을 지나도 화면이 스스로 막지 않는다'로 바뀌었다.
- 만료된 선점으로 결제하려면 '결제하기'를 눌러 서버의 `409 HOLD_EXPIRED`를 받아야 막힌다. 그 전까지는 버튼을 누를 수 있다.
