# 0051. 좌석 배치 격자: 1번째 줄이 무대 쪽이고, 격자 크기는 좌석 위치의 최댓값으로 정한다

- 상태: 채택
- 날짜: 2026-11-27
- 결정한 사람: 에이전트가 제안, 사람이 확인(2026-11-27, Issue #35 세션. PR #37 리뷰 지적을 두고 "추천대로 진행")
- 관련: Issue [#35](https://github.com/Rasit-NP/curtain-call/issues/35), PR [#37](https://github.com/Rasit-NP/curtain-call/pull/37), 결정 [0046](0046-venue-seat-layout.md), [0047](0047-seat-grid-position.md), spec 2.1

## 결정

- 배치 격자의 1번째 줄(`gridRow` = 1)이 무대 쪽이다. 화면은 1번째 줄을 맨 위(무대 가까이)에 그린다.
- 격자 크기(줄 수·칸 수)는 API가 따로 주지 않는다. 화면은 그 공연 좌석의 `gridRow` 최댓값을 줄 수로, `gridColumn` 최댓값을 칸 수로 쓴다.
  - 예: 좌석이 1~5번째 줄, 1~9번째 칸에 있으면 5줄 9칸 격자다. 좌석이 없는 칸(예: 모든 줄의 5번째 칸)이 통로로 보인다.
  - 좌석이 있는 칸보다 바깥쪽(맨 오른쪽 칸 너머, 맨 아래 줄 너머)의 빈 줄·칸은 표현되지 않는다. 바깥쪽 빈칸은 화면에 의미가 없어 필요 없다.
    맨 위 줄·맨 왼쪽 칸이 비는 경우는 표현된다(위치가 1부터 세므로 그 너머의 좌석이 최댓값을 정한다).

## 근거

- 예매 화면은 보통 무대를 위쪽에 두고 좌석을 그 아래로 그린다. 방향을 정해 두지 않으면 좌석 선택 화면(3단계)이 위아래를 뒤집어 그릴 수 있다.
- 격자 크기는 좌석 위치에서 계산되므로, 응답 필드를 더하지 않아도 화면이 그릴 수 있다(응답 형식은 0047 그대로).

## 고려했지만 고르지 않은 것

- 응답에 격자 크기(`gridRows`·`gridColumns`)를 더함: 바깥쪽 빈칸까지 표현되지만, 쓸 곳이 없고 응답 형식(API 계약)이 늘어난다.
- 방향을 정하지 않고 3단계에서 정함: 시드 배치(가로 통로, A줄의 양 끝 빈자리)가 이미 '1번째 줄 = 무대 쪽'을 가정하고 있다.

## 적용과 남은 점

- spec 2.1 '좌석 위치'에 적었다. 좌석 선택 화면(3단계)이 이대로 그린다.
