# 0045. 결정 상태는 결정한 사람으로 정한다: '제안'은 물었을 때만, 확인받지 않은 에이전트 결정은 '에이전트 결정'

- 상태: 채택
- 날짜: 2026-11-27
- 결정한 사람: 사람(2026-11-27 메인 세션 대화). 상태 이름 `에이전트 결정`과 애매한 기존 결정의 처리는 2026-11-27 Issue #33 세션에서 사람이 골랐다.
- 관련: Issue [#33](https://github.com/Rasit-NP/curtain-call/issues/33), 결정 [0044](0044-ask-policy-before-implementing.md), 결정 [0024](0024-docs-two-tracks.md)

## 결정

- `채택`: 사람이 정했거나 확인한 결정.
- `제안`: 사람에게 물었고 답을 기다릴 때만 쓴다. 답을 받으면 답대로 적고 `채택`으로 바꾼다.
- `에이전트 결정`(새 상태): 에이전트가 정하고 사람이 확인하지 않은 결정. PR이 병합돼도 바꾸지 않는다. 사람이 확인하면 그때 `채택`으로 바꾼다.
- `대체됨(→NNNN)`: 그대로 둔다.
- 확인은 사람이 그 결정을 두고 답한 것이다. PR 병합과 보고 뒤 무응답은 확인이 아니다.
- '결정한 사람'에 사람과 에이전트가 함께 있으면, 사람이 정하거나 확인하지 않은 내용이 남아 있는 한 `에이전트 결정`이다.

main에 있던 결정 0001~0043의 상태를 이 정의로 다시 매겼다. 결정 내용은 바꾸지 않았다.

## 근거

- 예전 정의는 `제안`을 "PR 병합 전 또는 사람 확인 대기"로 둬, 묻지 않아도 `제안`이 붙고 PR이 병합되면 `채택`이 됐다. 병합이 곧 승인으로 처리돼, 사람이 정한 결정과 에이전트가 정한 결정을 상태로 구분할 수 없었다.
- 이름을 `에이전트 결정`으로 한 이유: 누가 정했는지가 상태에 바로 드러나고, '사람이 모든 결정을 확인해야 한다'는 뜻을 주지 않는다. 사람은 고칠 부분만 말하기로 했다(2026-11-27).
- 애매한 것을 `에이전트 결정`으로 둔 이유: 병합과 무응답은 확인이 아니라는 새 정의를 그대로 따른다. 사람이 정한 부분은 각 파일의 '결정한 사람'에 이미 적혀 있다.

## 고려했지만 고르지 않은 것

- 상태 이름 `미확인`: 확인이 빠진 점은 더 드러나지만, 답을 기다리는 `제안`과 헷갈린다.
- 상태 이름 `에이전트 결정(미확인)`: 확인되면 `채택`이 되므로 '(미확인)'이 겹친다.
- 애매한 것은 `채택` 유지: 지금 상태를 덜 바꾸지만, 병합을 확인으로 보던 옛 판단이 남는다.

## 적용과 남은 점

- 앞으로 PR이 병합돼도 결정 상태를 바꾸지 않는다. 사람이 확인한 결정만 `채택`으로 바꾼다.
- 목차와 파일의 상태가 같은지는 하네스가 검사하지 않는다(목차 검사는 링크만 본다). 이번에는 스크립트로 43개를 한 번 대조했다.
