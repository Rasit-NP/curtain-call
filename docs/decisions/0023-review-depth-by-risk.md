# 0023. 리뷰 강도는 PR 위험도로 정하고 항상 명시

- 상태: 채택
- 날짜: 2026-11-26
- 결정한 사람: 사람 지적, 에이전트 제안
- 관련: Issue [#9](https://github.com/Rasit-NP/curtain-call/issues/9), PR [#10](https://github.com/Rasit-NP/curtain-call/pull/10)

## 결정

`/code-review`에 강도를 항상 명시한다. 규칙 코드 `high`, 일반 기능 `medium`, 골격·설정·문서 `low`. `max`·`ultra`는 사람이 요청할 때만. 리뷰 에이전트가 재현한 후보는 다시 검증하지 않고, 중요한 결함이 나오면 먼저 보고하고 계속할지 묻는다.

## 근거

- 골격 PR 두 건(#7, #8)을 기억된 `max` 강도로 리뷰해 에이전트 약 35개와 긴 시간을 썼다. 사람이 시간이 지나치다고 지적했다.
- 꼼꼼함은 필요하지만, 들이는 비용은 위험도에 맞아야 한다. 규칙 코드에는 지금처럼 깊은 리뷰를 유지한다.

## 고려했지만 고르지 않은 것

- 일괄로 낮춤: 규칙 코드 리뷰가 얕아진다.
- 훅으로 강제: 규칙만으로 부족하면 그때 추가한다.
