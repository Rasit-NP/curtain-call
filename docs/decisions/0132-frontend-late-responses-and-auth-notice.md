# 0132. 프론트: 떠난 뒤 온 선점 성공은 해제하고, 떠난 뒤 온 로그인 성공은 토큰만 저장한다. AUTH_REQUIRED 문구는 로그인 화면에만 보인다

- 상태: 에이전트 결정
- 날짜: 2026-11-28
- 결정한 사람: 에이전트. 2026-11-27 Issue #52 세션에서 로드맵 #13이 넘긴 미정 정책마다 선택지·추천·근거를 보였고, 사람이 9·10·12번에 "추천대로"라고 맡겼다.
- 관련: Issue [#52](https://github.com/Rasit-NP/curtain-call/issues/52) '로드맵에서 넘겨받은 것', 명세 1·3.3·7.1·7.2·7.6, 결정 [0041](0041-frontend-login-return-path.md), [0043](0043-frontend-auth-required-sent-token.md), [0082](0082-frontend-seat-selection-impl.md)

## 결정

9. **좌석 선택 화면: 선점 요청 중 화면을 떠났는데 나중에 `201`이 오면** 결제 화면으로 이동하지 않고 그 선점을 해제(`DELETE /api/holds/{id}`)한다. 해제가 실패해도 알리지 않는다. 그때 저장된 토큰이 없으면(로그아웃) 보내지 않는다.
10. **로그인 화면: 로그인 요청 중 화면을 떠났는데 나중에 성공 응답이 오면** 토큰은 저장하고(헤더가 '로그아웃'으로 바뀜) 화면은 옮기지 않는다.
12. **`AUTH_REQUIRED` 문구**: 결제 화면을 포함한 모든 화면은 요청이 `401 AUTH_REQUIRED`로 끝나도 '로그인이 필요합니다.'를 그리지 않는다. 이 문구는 공통 처리가 보낸 로그인 화면에서만 보인다.

## 근거

에이전트가 질문에 든 추천 근거다.

9. 명세 1장 5번 '결제 전에 다른 화면으로 가면 해제'에 맞다. 그대로 두면 선점이 5분간 남아 내 좌석도 '선택 불가'로 보이고 4석 한도에 들어간다. 선점 요청 중 이동을 막으면 응답이 `201`일 때 결제 화면으로 가야 해 사용자가 누른 곳과 어긋나고, 선점은 결제와 달리 돈이 걸리지 않아 결과를 보여 줄 필요가 없다.
   토큰이 없을 때 보내면 401을 받고, 토큰 없이 보낸 요청의 `AUTH_REQUIRED`는 공통 처리를 불러(0043) 로그아웃한 사용자를 로그인 화면으로 보낸다.
10. 아이디·비밀번호를 넣고 누른 것은 로그인하려는 뜻이라 로그인은 된다. 그 뒤에 다른 곳으로 간 것도 사용자의 뜻이라 끌고 가지 않는다.
12. 같은 문구가 두 번 나올 이유가 없다. 화면 읽기 프로그램은 요청한 화면의 알림과 로그인 화면의 알림을 두 번 읽을 수 있다. 화면마다 다르면 헷갈린다.

## 고려했지만 고르지 않은 것

9. 지금처럼 버림(5분 뒤 만료), 선점 요청 중 이동을 막음.
10. 토큰도 버림, 지금처럼 저장하고 돌아갈 화면으로 이동.
12. 지금처럼 그림, 결제 화면만 그리지 않음.

## 적용과 남은 점

- 명세 3.3·7.1·7.2·7.6에 반영했다.
- 9번에서 선점 요청이 응답 없음(시간 초과)으로 끝나면 선점 번호를 몰라 해제할 수 없다. 명세 8장의 남은 점 그대로다.
- 12번: 다시 로그인한 뒤에 끝난 이전 요청의 `AUTH_REQUIRED`는 공통 처리를 하지 않으므로(0043) 화면이 아무 문구도 없이 머문다. 전에는 로그인한 상태에서 '로그인이 필요합니다.'가 보였다.
- 사람이 맡긴 결정이므로 다시 확인을 구하지 않는다. 사람이 확인하면 `채택`으로 바꾼다(0045).
