# 0131. 프론트: 결제 화면 — 제목·정보, 예매 완료 표시, 결제 중 이동 막기, 해제를 기다린 뒤 이동, AUTH_REQUIRED는 해제하지 않음, 404 뒤 버튼, 문구 지우기

- 상태: 에이전트 결정
- 날짜: 2026-11-28
- 결정한 사람: 에이전트. 2026-11-27 Issue #52 세션에서 항목마다 선택지·추천·근거를 보였고, 사람이 아래 항목마다 "추천대로"라고 맡겼다. 사람이 자기 말로 정한 부분은 [0130](0130-frontend-payment-human.md)에 있다.
- 관련: Issue [#52](https://github.com/Rasit-NP/curtain-call/issues/52), 명세 7.3·7.8, 결정 [0043](0043-frontend-auth-required-sent-token.md), [0062](0062-frontend-load-status-role.md), [0080](0080-frontend-seat-selection-human.md)

## 결정

번호는 질문 번호다.

1. **화면 제목과 정보**: 제목(h1)은 '결제'다. 그 아래에 공연 제목(h2), `일시 · 장소`, `좌석 A1, A2`, `금액 60,000원`을 한 줄씩 보여 준다.
5. **예매 완료(`201`)**: 제목을 '예매 완료'로 바꾸고 '예매가 완료되었습니다.'(`role="status"`)를 보여 준다. 그 아래에 공연 제목, `일시 · 장소`, `좌석`, `금액`(결제 응답의 예매 값)과 '내 예매' 링크를 둔다. 결제 버튼과 '뒤로 가기'(13번, 0130), 제한 안내는 지운다.
6. **결제 요청 중(응답 전)에 다른 화면으로 가려 하면**: 응답이 올 때까지(길어야 10초) 이동을 막는다. 뒤로가기·헤더 메뉴·로그아웃·링크를 눌러도 화면에 머물고, 요청 중에는 '결제를 처리하는 중입니다.'(`role="status"`)를 보여 준다. 응답을 받은 뒤 다시 누르면 평소대로 이동한다(승인이면 해제 없이, 아니면 해제하고).
7. **해제를 기다린 뒤 이동**: 해제 응답(또는 실패)을 받은 뒤 이동한다. 그동안 결제 버튼을 막는다. 로그아웃은 해제를 보낸 뒤 토큰을 지운다.
8. **`401 AUTH_REQUIRED`로 로그인 화면에 갈 때**: 해제를 보내지 않는다. 다시 로그인하면 결제 화면으로 돌아오고, 5분 안이면 같은 선점으로 결제를 이어 간다.
14. **결제 응답이 `404 NOT_FOUND`**: 결제 버튼을 지우고 안내 문구와 '내 예매' 링크를 보여 준다. `409 HOLD_EXPIRED`는 처음 추천('결제 버튼을 지운다')을 0130이 '남기고 누를 수 없게'로 바꿨다.
15. **안내 문구를 지우는 때**: '결제하기'를 다시 누르면 이전 문구를 지운다.

2번(남은 시간 형식)과 4번(남은 시간의 기준 시계)도 처음에 "추천대로"였으나, 뒤이은 답에서 사람이 시계를 빼기로 해([0130](0130-frontend-payment-human.md)) 쓸 일이 없어졌다.

## 근거

에이전트가 질문에 든 추천 근거다.

1. 좌석 선택·내 예매 화면처럼 하는 일을 제목으로 둔다. 좌석·금액 줄은 내 예매 화면과 같은 모양이라 결제 전후로 같은 글자가 보인다.
5. 결제가 끝나면 버튼이 남으면 다시 눌러야 할 것처럼 보인다. 완료 문구는 오류가 아니므로 `alert`가 아니라 `status`다(0062와 같은 기준).
6. 돈이 걸린 요청이라 사용자가 결과를 보고 떠나야 한다. 해제를 보내고 떠나면 결제와 해제가 경쟁해(명세 2.4) 결제가 됐는지 모른 채 떠나고, 응답 뒤 저절로 이동하면 승인돼도 완료 화면을 못 본다.
7. 바로 이동하면 뒤로가기로 돌아간 좌석 선택 화면이 해제보다 먼저 좌석을 불러와, 방금 내 좌석이 '선택 불가'로 보일 수 있다(PR #43에서 넘긴 점, 0080 남은 점). 해제는 보통 짧고, 실패해도 이동한다(명세).
8. 토큰이 이미 지워져 해제는 다시 401로 실패하고, 그 401이 공통 처리를 한 번 더 부른다(0043 남은 점).
14. 이미 결제·해제돼 이 선점으로는 다시 결제할 수 없다. `402`와 그 밖의 오류는 다시 결제할 수 있어 버튼을 남긴다.
15. 좌석 선택·로그인 화면과 같다.

## 고려했지만 고르지 않은 것

1. 제목 '결제·예매 확인'(명세의 화면 이름), 공연 제목을 h1로.
5. 제목 '결제'를 그대로 두고 완료 문구만 더함, 남은 시간도 남김.
6. 해제를 보내고 바로 이동, 해제 없이 바로 이동, 응답 뒤 저절로 이동.
7. 해제를 보내고 바로 이동.
8. 해제를 보냄.
14. 버튼을 남김.
15. 다른 문구가 나올 때까지 남김.

## 적용과 남은 점

- 명세 7.3·7.8에 반영했다.
- 사람이 맡긴 결정이므로 다시 확인을 구하지 않는다. 사람이 확인하면 `채택`으로 바꾼다(0045).
