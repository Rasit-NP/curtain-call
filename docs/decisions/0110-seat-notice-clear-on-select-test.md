# 0110. 프론트: '좌석을 고르면 안내 문구를 지운다'는 선점 요청의 409 HOLD_LIMIT_EXCEEDED 뒤에 좌석을 고르는 새 테스트로 검증하고, 기존 테스트 이름은 '취소'만 말하게 바꾼다

- 상태: 에이전트 결정
- 날짜: 2026-11-27
- 결정한 사람: 에이전트(Issue #47이 '에이전트가 정하는 것'으로 맡김)
- 관련: Issue [#47](https://github.com/Rasit-NP/curtain-call/issues/47), 결정 [0081](0081-frontend-seat-selection-recommended.md)

## 결정

- 새 테스트 `R2: 선점 요청이 409 HOLD_LIMIT_EXCEEDED로 끝나 뜬 안내 문구는 좌석을 하나 더 고르면 지운다`를 더한다.
  2석을 고르고 '좌석 선택 완료'를 눌러 `409 HOLD_LIMIT_EXCEEDED` 문구를 띄운 뒤, 세 번째 좌석을 고르면 문구가 사라지고 고른 좌석이 3석이 되는지 본다.
- 기존 테스트 `R2: 안내 문구는 좌석을 고르거나 취소하면 지우고, 5번째 좌석을 다시 누르면 다시 보인다`는 검증 내용은 그대로 두고, 이름만 실제로 지나는 경로대로 `R2: 5번째 좌석을 눌러 뜬 안내 문구는 좌석을 취소하면 지우고, 5번째 좌석을 다시 누르면 다시 보인다`로 바꾼다.

## 근거

- 5번째 좌석으로 문구를 띄우면 이미 4석을 고른 상태라 좌석을 더 고를 수 없다. 문구가 뜬 채 좌석을 '고를' 수 있는 상태는 선점 요청이 실패해 고른 좌석이 4석 미만으로 남을 때뿐이다(명세 7.2).
- 그런 실패 가운데 `409 HOLD_LIMIT_EXCEEDED`는 R2 문구이고, 이미 가진 좌석 때문에 실패한 사용자가 좌석을 다시 고르는 실제 흐름이다. `SEAT_ALREADY_HELD`는 고른 좌석을 비우므로 맞지 않는다.
- 기존 테스트 이름이 '고르거나'를 말하면 대응표와 이름만 보고 이 경로가 검증된다고 읽게 된다. 이번 공백이 그렇게 가려졌다.

## 고려했지만 고르지 않은 것

- 기존 테스트에 '고르기' 단계를 덧붙이기: 기존 테스트는 4석에서 시작해 '고르기'로 문구를 띄울 수 없다. 선점 요청까지 넣으면 한 테스트가 두 가지 흐름을 검증해 실패 원인을 읽기 어렵다.
- 404, 500, 응답 없음까지 모두 `it.each`로 돌리기: 문구를 지우는 코드는 실패 종류와 관계없이 한 곳(좌석을 고를 때)이라 한 경우로 그 코드를 지난다.

## 적용과 남은 점

- `SeatSelectPage.tsx`에서 좌석을 고를 때의 `setNotice(null)`을 지우면 새 테스트만 실패하는 것을 확인했다(32개 중 1개 실패).
