# 0003. 선점 1건은 좌석 묶음(1~4석), 결제는 선점 1건

- 상태: 채택
- 날짜: 2026-11-26
- 결정한 사람: 사람
- 관련: Issue [#3](https://github.com/Rasit-NP/curtain-call/issues/3), PR [#4](https://github.com/Rasit-NP/curtain-call/pull/4), `docs/spec.md` 9장

## 결정

좌석을 고르는 동안에는 서버에 아무것도 잡지 않고, '좌석 선택 완료'에서 고른 좌석을 한 번에 선점한다. 묶음은 전부 잡히거나 하나도 잡히지 않는다. 결제 요청은 `holdId` 하나를 받는다.

## 근거

- 사람이 CGV 예매 방식을 기준으로 정했다.
- E2E 시나리오 1(좌석 2석 선점 → 결제)과 맞고, 결제 한 번에 예매 하나가 생겨 R5(멱등 키)를 단순하게 유지한다.

## 고려했지만 고르지 않은 것

- 좌석 1개 = 선점 1건: 결제가 여러 선점을 받아야 하고 일부만 만료되는 경우를 다뤄야 한다.

## 적용과 남은 점

R1 교착 상태를 막으려고 좌석은 언제나 `id` 오름차순으로 잠근다(spec 2.4).
