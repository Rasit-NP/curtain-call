# 0027. Issue 작업은 Issue마다 별도 세션과 그 세션의 git 워크트리에서, 메인 체크아웃은 고치지 않는다

- 상태: 채택
- 날짜: 2026-11-26
- 결정한 사람: 사람(대화에서 지시)
- 관련: Issue [#29](https://github.com/Rasit-NP/curtain-call/issues/29)

## 결정

Issue 작업은 Issue마다 별도 세션에서, 그 세션의 git 워크트리로 한다. 메인 체크아웃(원래 저장소 폴더)의 파일은 고치지 않는다. 메인 세션은 Issue 등록, 세션 시작, 결과(PR, 검증 요약) 확인을 맡는다. 루트 `CLAUDE.md` '작업 흐름'의 'Issue별 세션'에 둔다.

## 근거

- #27·#28 작업 지시를 받은 에이전트가 메인 체크아웃에서 직접 구현하려 했다. 사람이 "하위 워크트리를 생성해서 하라"고 바로잡았다.
- 앞선 #5·#6은 각각 별도 세션과 워크트리(`.claude/worktrees/`)에서 진행했다. 규칙이 저장소에 없어 세션마다 판단이 달랐다.
- 에이전트의 개인 메모리는 규칙을 대신하지 못한다([0026](0026-issue-creation-scope.md)과 같은 이유).

## 고려했지만 고르지 않은 것

- 에이전트 개인 메모리에만 남기기: 다른 세션과 컴퓨터에 적용되지 않는다.
- 규칙만 두기: 같은 실수를 다시 할 수 있어, `Edit`·`Write`·`NotebookEdit`는 훅으로도 막는다([0029](0029-guard-main-checkout-hook.md)).

## 적용과 남은 점

- 워크트리의 브랜치 이름도 `<type>/<이슈번호>-<짧은-설명>`을 따른다. 앱이 만든 워크트리는 다른 이름으로 시작할 수 있어 바꾼다.
- PR 병합 뒤 결정 상태를 `채택`으로 바꾸는 것 같은 작은 문서 수정도 워크트리 세션에서 한다.
