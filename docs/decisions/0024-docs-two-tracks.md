# 0024. 문서화를 작업용 결정 기록과 포트폴리오용 진행 기록으로 나눈다

- 상태: 제안(PR 병합 전)
- 날짜: 2026-11-26
- 결정한 사람: 사람
- 관련: Issue [#11](https://github.com/Rasit-NP/curtain-call/issues/11)

## 결정

`docs/decisions/`(이 폴더)는 결정 하나에 파일 하나로, 에이전트가 작업 중에 지금 유효한 결정을 확인한다. `docs/history/`는 Issue 하나에 파일 하나로, 프로젝트가 끝난 뒤 사람이 어떤 상황에서 무엇을 어떤 근거로 골랐는지 읽는다. 둘 다 PR마다 그때그때 갱신한다.

## 근거

- 프로젝트를 포트폴리오로 쓰려면 판단의 근거가 남아야 하는데, 지금은 Issue·PR·대화에 흩어지고 대화의 판단은 사라진다.
- 독자와 목적이 다르다. 에이전트는 짧은 현재 상태가, 사람은 시간 순서의 근거가 필요하다.
- 판단이 수백 개가 되므로 문서 하나에 모으면 찾기 어렵다. 파일을 나누고 목차를 하네스로 검사한다.

## 고려했지만 고르지 않은 것

- 문서 하나(`decisions.md`): 커지면 찾기 어렵다.
- 끝난 뒤 몰아서 정리: 근거가 사라진다.

## 적용과 남은 점

`docs/agent-log.md`(결함 한 줄 기록)는 그대로 두고 history에서 링크한다.
