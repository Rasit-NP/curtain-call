# 0029. 메인 체크아웃 파일 수정을 PreToolUse 훅으로 막고, 메인 워크트리는 git으로 판단한다

- 상태: 제안(PR 병합 전)
- 날짜: 2026-11-26
- 결정한 사람: 사람(대화에서 지시). 판단 세부는 [0030](0030-guard-undecidable-input.md)(에이전트)
- 관련: Issue [#29](https://github.com/Rasit-NP/curtain-call/issues/29)

## 결정

`.claude/settings.json`에 `PreToolUse` 훅(`.claude/hooks/guard-main-checkout.sh`, 대상 도구 `Edit|Write|NotebookEdit`)을 둔다.

- 대상 파일이 이 저장소의 메인 워크트리(링크된 워크트리가 아닌 원래 체크아웃)에 있으면 종료 코드 2로 막고, 이유와 할 일(별도 워크트리 세션에서 작업)을 stderr로 알린다.
- 메인 워크트리인지는 경로 접두사가 아니라 git으로 판단한다. 파일이 속한 폴더에서 `git rev-parse --git-dir`와 `--git-common-dir`가 같으면 메인 워크트리다.
- 아직 없는 파일은 가장 가까운 기존 상위 폴더로 판단한다. 저장소 밖 파일(에이전트 메모리, 스크래치패드)은 막지 않는다.
- 하네스 테스트(`scripts/harness.test.sh`)로 막힘·통과 경우를 검사한다.

## 근거

- 규칙([0027](0027-issue-per-worktree-session.md))만으로는 같은 실수를 다시 할 수 있다. 훅은 저장소 설정이라 이 저장소에서 여는 모든 세션에 적용된다.
- 링크된 워크트리 `.claude/worktrees/<이름>/`은 경로상 메인 체크아웃 폴더 안에 있다. 경로 접두사로 판단하면 워크트리 세션의 정상 작업까지 막힌다.

## 고려했지만 고르지 않은 것

- 경로 접두사로 판단: 위 이유로 기각.
- Bash까지 막기: Bash 명령이 쓰는 파일(리다이렉션, `sed -i`, 스크립트, `git checkout` 등)을 믿을 만하게 알아낼 수 없다. Bash를 통째로 막으면 메인 세션의 `gh`·`git` 조회도 막힌다.

## 한계

- **Bash로 파일을 쓰는 경우는 막지 못한다.** 루트 `CLAUDE.md`에 "훅이 막지 못하는 Bash로도 고치지 않는다"고 적어 규칙으로 막는다. 이 훅은 실수를 막는 장치이지 보안 경계가 아니다.

## 적용과 남은 점

- 병합되면 메인 체크아웃에서 실행하는 세션은 저장소 파일을 `Edit`·`Write`로 고칠 수 없다. 의도한 동작이다.
- 메인 체크아웃에 main을 받아 `settings.json`이 바뀐 뒤 연 세션부터 적용된다. 이미 열린 세션에는 바로 반영되지 않을 수 있다.
- git이 무시하는 메인 체크아웃 파일(예: `.claude/settings.local.json`)도 막힌다. 이런 파일을 예외로 둘지는 사람이 정한다.
