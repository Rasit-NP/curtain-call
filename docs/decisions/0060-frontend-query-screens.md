# 0060. 프론트: 공연 목록·내 예매 화면 표시, 공통 헤더, 로그아웃

- 상태: 채택
- 날짜: 2026-11-27
- 결정한 사람: 사람(2026-11-27 메인 세션 대화, Issue #36 '이미 정한 정책')
- 관련: Issue [#36](https://github.com/Rasit-NP/curtain-call/issues/36), 명세 7.4·7.5·7.7·7.8

## 결정

- 공연 목록 화면(`/`, 로그인 필요 없음)
  - 공연마다 제목, 일시, 장소, 가격을 보여 주고, 항목 전체가 좌석 선택 화면(`/performances/{id}`) 링크다.
  - 일시는 한국 시간으로 `2026. 12. 20.(일) 19:00` 형식, 가격은 `30,000원` 형식이다.
  - 빈 목록은 '예정된 공연이 없습니다.', 로딩은 '불러오는 중입니다.', 오류는 명세 7.6의 code별 문구다.
- 내 예매 화면(`/reservations`, 로그인 필요)
  - API가 준 순서(최신순)대로 예매마다 제목, 일시·장소, 좌석(`A-1, A-2`), 금액을 보여 준다.
  - 빈 목록은 '예매 내역이 없습니다.'와 '공연 목록' 링크다. 로딩과 오류는 공연 목록 화면과 같다.
- 공통 헤더: 모든 화면 위에 '커튼콜'(공연 목록 링크), '내 예매'를 두고, 로그인 전에는 '로그인', 로그인 뒤에는 '로그아웃'을 둔다.
- 로그아웃: 서버 API 없이 토큰을 지우고 공연 목록(`/`)으로 보낸다.

## 근거

- 사람이 메인 세션에서 정해 Issue에 적었다. 명세 7.4는 표시 항목만 정했고, 빈 목록·헤더·로그아웃은 명세에 없었다.

## 고려했지만 고르지 않은 것

- 기록 없음(사람이 정한 값을 그대로 옮겼다).

## 적용과 남은 점

- 명세 7.4를 고치고 7.7(공연 목록)·7.8(공통 헤더와 로그아웃)을 더했다.
- 결제 화면에서 헤더로 이동하거나 로그아웃할 때의 선점 해제는 결제 화면 Issue(4단계)에서 만든다(명세 7.3 '메뉴 이동').
