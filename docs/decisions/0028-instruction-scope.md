# 0028. 사람의 마지막 지시에 적힌 일만 하고, 행동은 그 행동을 지시받은 뒤에 한다

- 상태: 채택
- 날짜: 2026-11-26
- 결정한 사람: 사람(대화에서 지시)
- 관련: Issue [#29](https://github.com/Rasit-NP/curtain-call/issues/29)

## 결정

루트 `CLAUDE.md` '작업 흐름'의 '지시 범위'에 둔다.

- 사람의 마지막 지시에 적힌 일만 한다.
- '제시·설명·검토'를 지시받으면 제안·설명만 한다.
- 세션 시작, Issue 생성, 파일 수정, PR 같은 행동은 사람이 그 행동을 지시한 뒤에 한다.
- 범위가 모호할 때만 한 번 묻는다.

## 근거

- 사람이 "앞으로 알아서 잘 하도록 하는 방법을 제시하라"고 했는데, 에이전트가 제안하지 않고 세션부터 띄웠다. 지시하지 않은 세션 시작을 두 번 취소당했다.
- Issue 13개를 만든 것([0026](0026-issue-creation-scope.md))도 지시를 글자 그대로 따르지 않고 에이전트의 해석으로 넓힌 결과였다.

## 고려했지만 고르지 않은 것

- 에이전트 개인 메모리에만 남기기: 다른 세션과 컴퓨터에 적용되지 않는다.

## 적용과 남은 점

- 이 저장소의 다른 절차(검증, 문서화, 사람에게 넘기기)와 함께 읽을 때, 'Issue를 진행하라'는 지시가 PR 생성까지 포함하는지는 문구만으로 모호할 수 있다. 지금은 지시에 'PR까지'를 적어 정한다. 문구를 더 정할지는 사람이 정한다.
