# 0006. 멱등 키는 사용자별, 검증을 통과한 결제 결과는 모두 저장, 같은 키 동시 요청은 기다림

- 상태: 채택
- 날짜: 2026-11-26
- 결정한 사람: 에이전트 제안, 사람 병합(같은 키·다른 선점 400은 사람 결정)
- 관련: Issue [#3](https://github.com/Rasit-NP/curtain-call/issues/3), PR [#4](https://github.com/Rasit-NP/curtain-call/pull/4), `docs/spec.md` 6.7.1

## 결정

(`userId`, `idempotencyKey`) 복합 유니크. 검증을 통과한 요청은 201·402·404·409 결과를 모두 저장한다. 같은 키에 다른 `holdId`는 `400 INVALID_INPUT`. 같은 키 요청이 동시에 오면 먼저 요청이 끝날 때까지 기다렸다가 저장된 응답을 준다.

## 근거

- 독립 리뷰에서 404·409를 저장하지 않으면 '같은 키, 다른 선점은 400'(사람 결정)과 충돌한다는 것을 찾았다(`docs/agent-log.md`).
- 독립 리뷰에서 '저장된 응답 확인 → 선점 확인' 순서면 동시 요청이 404를 받는다는 R5 위반을 찾았다. 그래서 같은 키를 먼저 잡고 기다린다.
- IETF Idempotency-Key 초안은 처리 중인 같은 키에 409를 권하지만, R5의 '같은 결과'를 지키고 새 코드를 만들지 않으려고 기다리기로 했다.

## 고려했지만 고르지 않은 것

- 처리 중이면 409: 새 오류 코드가 필요하고 R5의 같은 결과와 어긋난다.
- 201만 저장: 위 충돌.

## 적용과 남은 점

멱등 기록은 결제와 따로 둔다(spec 2.1).
