# 0049. 공연 시드: 배치가 다른 공연장 2곳, 공연 3개, 모든 좌석 AVAILABLE. 시드 테스트는 값이 아닌 성질만 본다

- 상태: 에이전트 결정
- 날짜: 2026-11-27
- 결정한 사람: 에이전트(사람이 시드 값은 샘플 데이터라 묻지 말라고 정함, 2026-11-27 메인 세션 대화)
- 관련: Issue [#35](https://github.com/Rasit-NP/curtain-call/issues/35), 결정 [0036](0036-seed-accounts.md), [0048](0048-venue-performance-schema.md), spec 2.5

## 결정

- `db/seed/V1001__seed_venues.sql`: 공연장과 배치.
  - 대학로 커튼홀: A~E 5줄, 줄마다 8석(40석). 4번과 5번 사이(격자 5번째 칸)가 세로 통로.
  - 혜화 다락극장: 30석. A줄은 6석이라 양 끝 칸이 빈자리, B줄과 C줄 사이(격자 3번째 줄)가 가로 통로.
- `db/seed/V1002__seed_performances.sql`: 공연과 공연 좌석.
  - 작은 방의 햄릿(대학로 커튼홀) 2회차: 2027-01-15 19:00, 2027-01-16 14:00(한국 시간), 30,000원.
  - 다락방의 갈매기(혜화 다락극장): 2027-01-22 20:00(한국 시간), 25,000원.
  - 공연 좌석은 공연장 배치를 복사하고 모두 `AVAILABLE`이다.
- id를 정하지 않고 이름으로 이어 붙인다. E2E는 id를 가정하지 않는다(spec 6.9).
- 시드 테스트(`PerformanceSeedTest`)는 결정 0036처럼 테이블을 비운 뒤 시드 파일을 직접 실행하고, 값이 아니라 성질을 본다.
  - spec 2.5 최소 조건: 공연 2개 이상, 공연 상세마다 `AVAILABLE` 5석 이상(API로 확인).
  - 공연 좌석이 그 공연장 배치와 같다.
  - 배치가 서로 다른 공연장이 2곳 이상이고, 격자 안에 좌석이 없는 칸이 있는 배치가 있다.
- 시드 파일 실행은 `support.SeedFiles`로 모아 계정 시드 테스트(`E2eProfileAuthTest`)와 함께 쓴다.

## 근거

- Issue #35의 조건: spec 2.5 최소 조건, 공연장마다 다른 배치, 통로나 빈자리가 있는 배치 포함.
- 같은 공연장의 공연을 2회차 두어 '같은 공연장의 공연은 같은 배치'를 시드에서도 보인다.
- 선점·예매가 없는 좌석을 `HELD`·`SOLD`로 두면 좌석을 잡은 선점(`holdId`)이 없는 상태가 된다(spec 2.1).
- 공연 일시는 오늘(2026-11-27) 뒤로 두어 시연할 때 지난 공연으로 보이지 않게 했다. 지난 공연이어도 기능은 같다(spec 8).
- 시드 값은 샘플 데이터이므로, 값을 바꿔도 테스트가 깨지지 않게 성질만 확인한다.

## 고려했지만 고르지 않은 것

- 공연장 1곳: '공연장마다 다른 배치'를 보일 수 없다.
- 시드 값(제목, 좌석 수)을 그대로 확인하는 테스트: 샘플 데이터를 바꿀 때마다 테스트를 고쳐야 한다.

## 적용과 남은 점

- E2E reset 컨트롤러(6단계)는 같은 시드 파일을 다시 실행한다.
