# 0181. 회원가입을 만든다(필수). 범위 밖 목록에서 빼고, 세부 정책은 로드맵 2의 3단계 Issue에서 정한다

- 상태: 채택
- 날짜: 2026-11-28
- 결정한 사람: 사람(2026-11-28 메인 세션)
- 관련: 로드맵 2 [#64](https://github.com/Rasit-NP/curtain-call/issues/64), Issue [#65](https://github.com/Rasit-NP/curtain-call/issues/65), 결정 [0180](0180-roadmap2-transition.md), [0036](0036-seed-accounts.md), spec 2.1, 8장

## 결정

- 회원가입을 만든다. 로드맵 2의 필수 항목이다.
- 루트 `CLAUDE.md` '금지 사항'과 명세 8장의 범위 밖 목록에서 회원가입을 뺀다.
- 명세 2.1의 사용자는 "지금은 시드로만 만든다. 회원가입은 로드맵 2의 3단계 Issue에서 정한다"로 고친다.
- 세부 정책은 이 결정에 적지 않는다. 받는 항목, 아이디·비밀번호 규칙, API와 응답, 중복 아이디 오류 코드, 새 규칙 후보 R7(같은 아이디로 동시에 가입하면 한 명만 성공), 화면 흐름은 3단계 Issue에서 사람이 정한다.

## 근거

- 사람이 회원가입을 필수로 정했다(#64 '정한 것').
- 범위 밖 목록에 남겨 두면 3단계 Issue 세션이 '범위 밖 기능을 만들지 않는다'에 걸린다. 그래서 0단계에서 범위를 먼저 바꾼다.
- 세부 정책은 계정·비밀번호·인증 정책이라 구현 전에 사람에게 묻는다(루트 `CLAUDE.md` '정책 결정'). 0단계에서 미리 정하지 않는다.

## 고려했지만 고르지 않은 것

- 명세 2.1에 회원가입 규칙의 초안을 함께 적기: 아직 정하지 않은 정책을 문서에 먼저 적게 된다. Issue #65가 '세부 규칙은 적지 않는다'로 정했다.

## 적용과 남은 점

- 코드 주석의 '회원가입은 없다'(`User.java`)는 3단계 백엔드 회원가입 Issue에서 고친다.
  `V1__create_users.sql`의 같은 주석은 main에 병합된 마이그레이션이라 고치지 않는다(Flyway 체크섬도 바뀐다).
- 시연·E2E 계정 시드([0036](0036-seed-accounts.md))는 그대로 둔다.
- 3단계 회원가입 Issue는 인증을 바꾸지만, 로드맵에 있는 Issue라 그 범위 안에서 고친다. 정책은 구현 전에 묻는다([0186](0186-handoff-roadmap-issue-scope.md)).
