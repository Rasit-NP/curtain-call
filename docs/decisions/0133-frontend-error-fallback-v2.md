# 0133. 프론트(개정): code가 없는 오류 응답은 INTERNAL_ERROR, 단 code가 없는 502·503·504는 응답 없음(NO_RESPONSE)

- 상태: 에이전트 결정
- 날짜: 2026-11-28
- 결정한 사람: 에이전트. 2026-11-27 Issue #52 세션에서 선택지·추천·근거를 보였고, 사람이 11번에 "추천대로"라고 맡겼다.
- 관련: Issue [#52](https://github.com/Rasit-NP/curtain-call/issues/52) '로드맵에서 넘겨받은 것', 명세 3.1·7.3·7.5, 결정 [0019](0019-frontend-no-response.md)
- 대체한 결정: [0018](0018-frontend-error-fallback.md)

## 결정

- 오류 응답 본문에 오류 코드 표의 `code`가 없거나 JSON이 아니면 `INTERNAL_ERROR`로 본다. 2xx인데 본문이 JSON이 아닌 경우도 같다(0018 그대로).
- 단, 상태가 502·503·504이고 본문에 오류 코드 표의 `code`가 없으면 응답 없음(`NO_RESPONSE`)으로 본다. 문구는 '서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요.'이고, 결제 화면은 다음에 누를 때 같은 멱등 키를 다시 쓴다(R5).
- 이 경우 `ApiError`의 `status`는 받은 상태(502 등)를 그대로 둔다. 화면은 `code`만 본다.

## 근거

- 0018의 남은 점: 개발 서버(Vite 프록시)는 백엔드가 꺼져 있으면 본문 없는 502를 줘, '서버에 연결할 수 없습니다' 대신 '일시적인 오류' 문구가 나오고 결제 화면이 새 멱등 키를 만들었다.
- 이 응답은 백엔드가 아니라 중간 서버(프록시)가 만든 것이다. 백엔드에 닿지 못했거나(502), 백엔드가 처리했는지 모른다(504). 문구는 '응답 없음'이 실제 상황에 맞고, 결과를 모르는 결제는 같은 키로 다시 보내야 안전하다(R5, 0019).
- 백엔드는 모든 오류 응답에 `code`를 붙이므로(명세 3.1) 백엔드가 직접 준 오류는 영향이 없다.

## 고려했지만 고르지 않은 것

- 0018 그대로: 위의 남은 점이 남는다.
- `status`도 `null`로 바꿈: 응답 자체는 받았으므로 상태를 지우지 않는다. 화면은 `status`를 쓰지 않는다.

## 적용과 남은 점

- `src/api/client.ts`에 반영했다. 0018의 테스트 두 개(code 없는 ProblemDetail, HTML 본문)는 502로 `INTERNAL_ERROR`를 기대했으므로, 명세 변경에 맞춰 상태를 500으로 바꾸고 502·503·504의 새 테스트를 더했다.
- 사람이 맡긴 결정이므로 다시 확인을 구하지 않는다. 사람이 확인하면 `채택`으로 바꾼다(0045).
