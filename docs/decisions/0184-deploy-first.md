# 0184. 지금까지 만든 것을 먼저 배포하고, 추가 기능은 그 뒤에 만든다

- 상태: 채택
- 날짜: 2026-11-28
- 결정한 사람: 사람(2026-11-28 메인 세션)
- 관련: 로드맵 2 [#64](https://github.com/Rasit-NP/curtain-call/issues/64)(2단계), Issue [#65](https://github.com/Rasit-NP/curtain-call/issues/65), 결정 [0180](0180-roadmap2-transition.md), [0186](0186-handoff-roadmap-issue-scope.md)

## 결정

로드맵 1에서 만든 것(R1~R6)을 로드맵 2의 2단계에서 먼저 배포한다. 회원가입, UI 다듬기, 예매 취소 같은 추가 기능은 배포한 뒤에 만든다.

## 근거

- 단계마다 배포되므로 어디서 멈춰도 제출할 수 있다(#64 '남은 순서').

## 고려했지만 고르지 않은 것

- 추가 기능을 모두 만든 뒤 한 번에 배포하기(이유는 #65 세션의 에이전트가 정리): 제출 직전에 배포 문제를 처음 만나게 되고, 중간에 멈추면 제출할 배포가 없다.

## 적용과 남은 점

- 호스팅·도메인, 배포 서버의 시연 데이터, 좌석 초기화 방식, 모의 결제 안내 문구는 2단계 전에 사람이 정한다(#64).
- 서버 생성과 GitHub Secrets 등록은 사람이 한다. 로드맵에 있는 배포 Issue가 배포 설정을 고쳐도 사람에게 넘기지 않지만, 비밀값이나 외부 계정이 필요한 일은 넘긴다([0186](0186-handoff-roadmap-issue-scope.md)).
