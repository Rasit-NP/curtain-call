# 0050. 공연 상세의 performanceId: long으로 해석할 수 없으면 400 INVALID_INPUT, 0·음수는 없는 공연(404)

- 상태: 에이전트 결정
- 날짜: 2026-11-27
- 결정한 사람: 에이전트
- 관련: Issue [#35](https://github.com/Rasit-NP/curtain-call/issues/35), 결정 [0012](0012-backend-error-mapping.md), spec 3.1, 6.3

## 결정

- `GET /api/performances/{performanceId}`의 `performanceId`는 `long`으로 받는다.
- `abc`, `1.5`, `1e3`처럼 정수가 아니거나, `99999999999999999999`처럼 long 범위를 넘으면 경로 값 변환에 실패해 400 INVALID_INPUT이다.
- `0`, `-1`은 정수이므로 400이 아니고, 그런 공연이 없어 404 NOT_FOUND다.

## 근거

- spec 6.3은 "정수가 아님"만 400으로 정했다. 0과 음수는 정수이므로 그대로 읽으면 404다.
- spec 3.1과 결정 0012가 경로 값의 형식 오류를 400 INVALID_INPUT으로 정했다. long 범위 밖의 값은 서버가 해석할 수 없는 형식이고, ID는 정수(spec 3)라 그런 공연은 만들 수 없다.
- 공통 처리기의 경로 값 변환 오류 처리를 그대로 써서 새 코드를 만들지 않는다.

## 고려했지만 고르지 않은 것

- 0·음수도 400: spec 6.3의 오류 표에 없는 검증을 더한다. 선점(6.4)의 '양수가 아님'은 본문 필드 검증이라 경우가 다르다.
- long 범위 밖은 404: 범위 밖 값을 따로 잡는 코드가 필요하고, 3.1의 형식 오류와 어긋난다.

## 적용과 남은 점

- 선점·결제의 경로 id(`holdId`)도 같은 방식이 된다. 사람이 다르게 정하면 새 결정으로 바꾼다.
