## 결정

로드맵 1(MVP, R1~R6) #13을 닫고, 로드맵 2 #64로 구현 순서와 진행 상황을 본다.

- 0단계: 문서 전환(#65).
- 1단계: CI(GitHub Actions, [0183](0183-github-actions.md))와 뮤테이션 테스트(PIT) 기준선.
- 2단계: 배포([0184](0184-deploy-first.md)).
- 3·4단계: 회원가입([0181](0181-signup-in-scope.md))과 UI 다듬기(상용 서비스 수준), k6 부하 테스트, README(#60).
- 5~7단계(선택): 예매 취소, 좌석 실시간 반영(SSE + PostgreSQL LISTEN/NOTIFY), 최종 측정과 제출 준비.
- 필수는 0~4단계, 선택은 5~7단계다. 만들지 않는 것은 [0182](0182-no-queue-no-performance-registration.md)에 있다.
- 단계와 순서, 단계마다 '먼저 사람이 정한다'는 #64 본문에 둔다. 순서를 바꾸거나 항목을 더하면 #64 본문을 고친다.

## 근거

- #13의 1~6단계가 모두 병합됐다. README(#60)는 UI 개편 뒤에 쓰기로 해(결정 0171, 아직 #60 브랜치에만 있다) 로드맵 2의 4단계로 옮겼다.
- 단계마다 배포되므로 어디서 멈춰도 제출할 수 있다(#64 '남은 순서').
- 같은 단계에서 고치는 폴더가 겹치지 않는 항목은 동시에 진행한다. 프론트엔드 화면은 MSW로 API를 흉내 내므로 백엔드를 기다리지 않는다.
