# 0186. 사람에게 넘기는 조건(개정): 로드맵에 있는 Issue는 그 Issue가 범위로 다루는 인증·보안, CI·배포 설정을 그 범위 안에서 고친다

- 상태: 채택
- 날짜: 2026-11-28
- 결정한 사람: 사람. CI·배포는 2026-11-28 메인 세션에서 정했고, 인증·보안은 2026-11-28 Issue #65 세션에서 사람이 선택지와 문구를 보고 골랐다.
- 관련: Issue [#65](https://github.com/Rasit-NP/curtain-call/issues/65), 로드맵 2 [#64](https://github.com/Rasit-NP/curtain-call/issues/64), 결정 [0010](0010-security-in-auth-issue.md), [0044](0044-ask-policy-before-implementing.md), [0181](0181-signup-in-scope.md), [0183](0183-github-actions.md), [0184](0184-deploy-first.md)

## 결정

루트 `CLAUDE.md` '사람에게 넘기는 조건'의 "인증·보안, CI·배포 설정, main에 병합된 마이그레이션을 바꿔야 한다"를 다음처럼 나눈다.

- main에 병합된 마이그레이션을 바꿔야 한다. (그대로 넘긴다.)
- 인증·보안, CI·배포 설정을 바꿔야 한다.
  단, 로드맵에 있는 Issue는 그 Issue가 범위로 다루는 인증·보안, CI·배포 설정을 그 Issue 범위 안에서 고친다. 정책은 '정책 결정'대로 구현 전에 묻는다.
- 비밀값이나 외부 계정이 필요하다. (그대로 넘긴다. 로드맵에 있는 Issue도 마찬가지다.)

## 근거

- CI·배포(메인 세션): 옛 문구대로면 로드맵 2의 1단계 CI Issue와 2단계 배포 Issue 세션은 시작하자마자 멈춰야 한다. 그 Issue가 하는 일 자체가 CI·배포 설정을 바꾸는 것이다.
  사람이 직접 해야 하는 일은 서버 생성과 GitHub Secrets 등록처럼 비밀값이나 외부 계정이 필요한 일이다.
- 인증·보안(Issue #65 세션에서 사람에게 물음): 같은 이유로 3단계 회원가입 Issue 세션도 시작하자마자 멈춰야 한다. 에이전트가 이 선택지를 추천했고, 근거는 다음과 같았다.
  - 1단계 인증 Issue #27은 옛 문구 아래에서 Issue 범위로 보고 진행했다. 문구를 실제 진행 방식에 맞춘다.
  - 계정·비밀번호·인증·보안은 이미 '정책 결정'에 들어 있어 구현 전에 세션에서 묻는다([0044](0044-ask-policy-before-implementing.md)). 넘기지 않아도 결정은 사람이 한다.
  - CI·배포와 같은 문구로 두면 세션이 두 조건을 다르게 읽지 않는다.
- 'Issue가 범위로 다루는'으로 좁힌 이유: 다른 기능을 만들다 인증·보안이나 CI·배포 설정을 바꿔야 하는 경우(예: 화면 Issue에서 보안 설정을 고쳐야 할 때)는 여전히 넘긴다.

## 고려했지만 고르지 않은 것

Issue #65 세션에서 사람에게 보인 선택지다.

- 인증·보안은 지금 문구 유지(항상 넘김): 가장 보수적이지만, 3단계 회원가입 세션이 시작하자마자 멈추고 사람이 Issue에서 진행을 허용해야 한다.
- 회원가입 Issue만 예외: 2단계의 'E2E 초기화 API를 운영에서 닫기'나 6단계 SSE의 로그인 필요 여부처럼 다른 단계의 보안 항목은 여전히 멈춘다.
