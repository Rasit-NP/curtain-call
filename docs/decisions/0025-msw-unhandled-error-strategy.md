# 0025. 프론트 테스트: 핸들러 없는 요청은 MSW 'error' 전략으로 막고, 테스트가 끝날 때 처리 중인 요청을 기다린다

- 상태: 에이전트 결정
- 날짜: 2026-11-26
- 결정한 사람: 에이전트(PR 리뷰 반영)
- 관련: Issue [#6](https://github.com/Rasit-NP/curtain-call/issues/6), PR [#7](https://github.com/Rasit-NP/curtain-call/pull/7)

## 결정

`server.listen({ onUnhandledFrame: 'error' })`로 핸들러가 없는 요청을 네트워크 오류로 끝내고, `request:unhandled` 이벤트로 기록한다. `afterEach`는 핸들러를 초기화하기 전에 처리 중인 요청을 기다린 뒤 기록을 검사하고, `afterAll`에서도 검사한다.

## 근거

- 처음에는 커스텀 `onUnhandledFrame` 콜백에서 `defaults.error()`를 불렀다. MSW 3.0.8에서 이 함수는 메시지만 찍고, 콜백이 정상으로 끝나면 요청을 실제 네트워크(jsdom origin `localhost:3000`)로 보낸다. 3000번에 프로세스가 있으면 토큰과 본문이 그쪽으로 나가고 테스트 결과가 기계에 따라 달라진다(리뷰에서 재현).
- 콜백에서 예외를 던지면 요청은 막히지만 500 응답이 된다. MSW `errorWith`는 자기 `InternalError`만 네트워크 오류로 바꾸기 때문이다. 그래서 내장 `'error'` 전략을 쓴다.
- MSW는 요청을 비동기로 처리해, 테스트가 끝날 때 막 보낸 요청(화면 이동 때의 선점 해제, 로딩 상태 테스트)이 다음 테스트 탓이 되거나 보고되지 않았다(리뷰에서 재현).

## 고려했지만 고르지 않은 것

- 콜백에서 예외 던지기: 위 이유로 500이 된다.
- 기록 없이 `'error'` 전략만: 클라이언트가 네트워크 오류를 '응답 없음'으로 바꿔, 응답 없음을 기대하는 테스트가 핸들러 없이 통과한다.

## 적용과 남은 점

`'error'` 전략으로 끝난 요청에는 MSW가 `request:end`를 보내지 않아, `request:unhandled`에서도 처리 중 목록에서 뺀다. 응답하지 않는 핸들러(시간 제한 테스트)는 최대 대기 시간까지만 기다린다.
