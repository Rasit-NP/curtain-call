# 0185. Issue 등록(개정): 로드맵 #64에서 지금 진행할 단계만, 본문 초안을 사람에게 보여 승인을 받은 뒤 등록한다

- 상태: 채택
- 날짜: 2026-11-28
- 결정한 사람: 사람(2026-11-28 메인 세션). 0026을 대체할지 보완할지는 Issue #65가 에이전트에게 맡겼고, 에이전트가 대체로 정했다.
- 관련: Issue [#65](https://github.com/Rasit-NP/curtain-call/issues/65), 로드맵 2 [#64](https://github.com/Rasit-NP/curtain-call/issues/64), 대체하는 결정 [0026](0026-issue-creation-scope.md), 결정 [0028](0028-instruction-scope.md), [0180](0180-roadmap2-transition.md)

## 결정

0026을 대체한다. 루트 `CLAUDE.md` '작업 흐름'의 'Issue 등록 범위'에 둔다.

- Issue를 만들어 달라는 요청에는 로드맵(#64)에서 지금 진행할 단계의 Issue만 만든다. (0026과 같고, 로드맵만 #13에서 #64로 바뀌었다.)
- 그보다 많이 만들어야 할 것 같으면 만들 목록을 먼저 보여 주고 묻는다. (0026과 같다.)
- Issue는 본문 초안을 사람에게 보여 승인을 받은 뒤 등록한다. 한 번 받은 승인은 그때 보여 준 Issue에만 적용한다. (새로 더했다.)

## 근거

- 사람이 "이슈를 등록하기 전에는 반드시 저의 승인을 거친 후 등록하도록 하세요"라고 했다(2026-11-28 메인 세션, 원문). 이 규칙은 메인 세션의 메모리에만 있어 다른 세션은 몰랐다.
  저장소 규칙에 없으면 새 세션마다 같은 판단을 다시 한다(0026의 근거와 같다).
- 승인을 그 Issue에만 적용하는 이유: 한 번 승인받은 것을 다음 Issue의 승인으로 넓히면, 지시를 에이전트의 해석으로 넓히는 것이 된다([0028](0028-instruction-scope.md)).
- Issue는 지워도 번호를 다시 쓰지 않는다(#14~#26). 등록한 뒤 고치는 것보다 등록 전에 확인하는 비용이 작다.

### 대체를 고른 이유(에이전트)

- 0026의 결정과 '적용과 남은 점'이 로드맵 #13을 직접 가리킨다. 0026을 `채택`으로 두고 보완만 하면 목차에서 닫힌 #13을 가리키는 결정이 유효한 것으로 보인다.
- 저장소 규칙은 결정이 바뀌면 원래 파일을 고치지 않고 새 파일을 만든다. 로드맵이 바뀌고 승인 절차가 더해져 0026의 결정 문장이 바뀌었다.
- 대체해도 0026의 근거(Issue 13개를 만든 일)는 0026 파일에 남는다.

## 고려했지만 고르지 않은 것

- 0026을 그대로 두고 승인 규칙만 새 결정으로 보완: 위 이유로 고르지 않았다.
- 메인 세션의 메모리에만 두기: 다른 세션과 컴퓨터에 적용되지 않는다(0026과 같다).

## 적용과 남은 점

- 로드맵 2의 1단계 Issue는 이 결정이 병합된 뒤 등록한다(#65 '선행').
- 지시 범위([0028](0028-instruction-scope.md))와 함께 적용한다. 승인받은 Issue를 등록하는 것도 등록하라는 지시를 받은 뒤에 한다.
