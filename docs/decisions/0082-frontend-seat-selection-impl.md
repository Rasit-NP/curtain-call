# 0082. 프론트: 좌석 선택 화면은 공연마다 새로 만들고, 409 뒤 다시 불러오기는 화면이 직접 하며 그동안도 막는다. 격자 위치는 인라인 스타일로 검증한다

- 상태: 에이전트 결정
- 날짜: 2026-11-27
- 결정한 사람: 에이전트
- 관련: Issue [#42](https://github.com/Rasit-NP/curtain-call/issues/42), 결정 [0065](0065-frontend-load-hook-and-screen-tests.md), [0080](0080-frontend-seat-selection-human.md), [0081](0081-frontend-seat-selection-recommended.md)

## 결정

- **공연마다 새 화면**: 라우트 요소 `SeatSelectRoute`가 주소의 공연 번호를 `key`로 `SeatSelectPage`를 만든다. 화면 안에서는 `useLoad`에 그 공연 번호로 고정된 `load` 함수를 넘긴다.
- **409 뒤 다시 불러오기**: `useLoad` 밖에서 화면이 `getPerformance`를 다시 부르고, 받은 공연 상세로 처음 것을 바꾼다. 실패하면 처음 것을 그대로 쓴다.
- **고른 좌석은 409를 받자마자 비운다**: 다시 불러오기를 기다리지 않는다. 다시 불러오기가 실패해도 고른 좌석은 빈 채다.
- **다시 불러오는 동안도 막는다**: '좌석 선택 완료'와 좌석 버튼은 선점 응답이 오고, `409 SEAT_ALREADY_HELD`면 다시 불러오기가 끝날 때까지 막는다.
- **좌석 버튼**: 보이는 글자는 표시 이름(`A3`), 접근성 이름은 `aria-label`(`A3 선택 가능`)이다. 상태가 이름에 들어 있으므로 `aria-pressed`는 쓰지 않는다.
- **안내 문구**: 문구를 보일 때마다 요소에 새 `key`를 줘 다시 그린다. 같은 문구(5번째 좌석을 다시 누름)도 화면 읽기 프로그램이 다시 읽게 하려는 것이다.
- **요청 본문**: `seatIds`는 고른 순서가 아니라 좌석 순서(`row`, `number`)로 담는다.
- **격자 위치 테스트**: 버튼의 인라인 스타일(`grid-row`·`grid-column`)과 격자의 `grid-template-rows`·`grid-template-columns`를 검사한다.

## 근거

- 공연마다 새 화면: 0065의 남은 점("`load`가 바뀌면 다시 불러오지만 로딩 상태로 돌아가지 않는다")을 피한다. 다른 공연으로 옮기면 고른 좌석과 문구도 함께 지워져야 하는데, `key`로 새로 만들면 상태를 하나씩 지우지 않아도 된다.
- 다시 불러오기를 `useLoad` 밖에서: 이 경우는 로딩 상태로 돌아가지 않고(0081의 9번), 실패해도 격자를 남겨야 해 `useLoad`의 상태 셋과 맞지 않는다.
- 409를 받자마자 비움: 사람의 답(0080)은 "선택을 비우고"를 다시 불러오기 결과에 걸지 않았다. 질문할 때의 문장 '실패하면 격자와 선택을 그대로'는 그때 추천이 '나머지 선택은 남긴다'였기 때문에 쓴 것이다.
- 다시 불러오는 동안 막음: 이때의 격자는 지난 상태라, 그 사이 고른 좌석이 이미 잡힌 좌석일 수 있다. 0081의 7번 '응답이 올 때까지 막는다'의 응답 처리에 다시 불러오기도 들어간다고 봤다. 보통 짧은 시간이다.
- `aria-label`: 보이는 글자가 이름의 앞부분이라, 음성 제어로 'A3'를 불러도 찾을 수 있다. `aria-pressed`를 같이 쓰면 '선택됨'과 '눌림'을 두 번 읽는다.
- 격자 위치: jsdom은 배치를 계산하지 않는다. 명세 5장의 계약("이 값을 CSS Grid의 `grid-row`·`grid-column`에 넣어 그린다")을 그대로 확인한다. jsdom이 이 속성을 읽는지, 값이 다르면 `toHaveStyle`이 실패하는지 먼저 확인했다.

## 고려했지만 고르지 않은 것

- `useLoad`에 다시 불러오기 함수를 더함: 로딩으로 돌아가지 않기, 실패해도 이전 데이터 유지가 다른 화면의 불러오기와 달라 훅이 복잡해진다.
- 다시 불러오기 결과를 받은 뒤에 고를 수 없게 된 좌석만 빼기: 그때까지의 명세였고, 사람이 '선택을 비운다'로 바꿨다.
- 격자를 ARIA `grid`로 만들어 `aria-rowindex`·`aria-colindex`로 검증: `grid` 역할은 화살표 키 이동을 함께 만들어야 하는 위젯이라, 버튼 묶음에 쓰면 잘못된 역할이 된다.

## 적용과 남은 점

- 화면을 떠난 뒤 온 응답은 버린다(화면이 사라졌으면 상태를 바꾸지 않고 이동도 하지 않는다).
- 다시 불러오는 동안 막는 동작은 사용자가 겪는 동작이다. 사람이 다르게 원하면 `submit`의 막는 범위만 바꾸면 된다.
