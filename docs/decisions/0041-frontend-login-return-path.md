# 0041. 프론트: 로그인 뒤 돌아갈 경로는 location state로 넘기고 앱 안의 경로만 받는다. 가드 이동에는 안내 문구를 붙이지 않는다

- 상태: 제안(PR 병합 전)
- 날짜: 2026-11-26
- 결정한 사람: 에이전트
- 관련: Issue [#28](https://github.com/Rasit-NP/curtain-call/issues/28)

## 결정

- 가드(`RequireAuth`)와 `AUTH_REQUIRED` 처리는 돌아갈 경로를 라우터 location state의 `from`(경로+쿼리+해시)으로 넘긴다. 로그인 화면은 로그인에 성공하면 `from`으로 `replace` 이동하고, 없으면 `/`로 간다.
- `from`은 `/`로 시작하고 `//`나 `/\`로 시작하지 않는 문자열만 받는다. 그 밖에는 `/`로 간다.
- 로그인 화면의 '로그인이 필요합니다.' 문구는 `AUTH_REQUIRED` 처리로 왔을 때(`notice: 'AUTH_REQUIRED'`)만 보여 준다. 토큰 없이 가드에 걸려 왔을 때는 보여 주지 않는다.

## 근거

- state는 URL에 드러나지 않고 다른 사이트가 만든 링크로 넣을 수 없다. 쿼리(`?redirect=`)는 외부 링크로 넣을 수 있어 열린 리다이렉트 검사가 더 중요해진다.
- 그래도 state 값은 검사한다. `//host`는 브라우저가 다른 사이트 주소로 읽는다.
- 안내 문구: spec 7.6은 `AUTH_REQUIRED` 문구를 '로그인 화면으로 보내면서 보여 준다'고 하고, 가드(spec 7.1)는 '`/login`으로 보낸다'만 정했다. 명세에 없는 동작을 더하지 않았다.

## 고려했지만 고르지 않은 것

- 쿼리로 넘기기: 위 이유. 새로고침해도 남는 장점은 있다.
- 가드 이동에도 문구 표시: 명세에 없다. 필요하면 사람이 정한다.

## 적용과 남은 점

- 로그인 화면에서 새로고침하면 브라우저 기록의 state는 남는다(`createBrowserRouter`). 새 탭에서 `/login`을 열면 `/`로 간다.
