# 0063. 프론트: 헤더의 로그인 상태는 토큰 저장소의 변경 알림으로 다시 그리고, 로그아웃은 일반 이동(push)으로 보낸다

- 상태: 에이전트 결정
- 날짜: 2026-11-27
- 결정한 사람: 에이전트
- 관련: Issue [#36](https://github.com/Rasit-NP/curtain-call/issues/36), 결정 [0043](0043-frontend-auth-required-sent-token.md)

## 결정

- `tokenStorage`의 `saveAccessToken`·`clearAccessToken`이 등록된 함수에 알리고(`subscribeAccessToken`), `useAccessToken` 훅이 `useSyncExternalStore`로 지금 토큰을 읽는다. 헤더는 이 훅으로 '로그인'·'로그아웃'을 고른다.
- 로그아웃은 토큰을 지운 뒤 `navigate('/')`로 보낸다. 기록을 바꾸지 않고(push) 쌓는다.
- 다른 탭에서 토큰이 바뀐 것(`storage` 이벤트)은 반영하지 않는다.

## 근거

- 토큰은 로그인 화면, 헤더, API 클라이언트(`AUTH_REQUIRED`) 세 곳에서 바뀐다. 저장소가 알리면 바꾸는 쪽이 헤더를 몰라도 된다. 상태 관리 라이브러리를 쓰지 않는다는 규칙(frontend/CLAUDE.md)에 맞게 React 기본 훅을 쓴다.
- 화면 이동이 있으면 헤더도 다시 그려지지만, 로그인 화면에서 늦게 온 `AUTH_REQUIRED`처럼 이동 없이 토큰만 지워지는 경우가 있다(0043: 로그인 화면이면 이동하지 않음). 테스트로 확인했다.
- 로그아웃 이동: Issue는 '공연 목록으로 보낸다'만 정했다. 링크를 누른 것과 같은 일반 이동으로 두었다. 뒤로가기로 내 예매에 가면 가드가 로그인 화면으로 보낸다.
- 다른 탭: Issue 범위('로그인, 로그아웃, `AUTH_REQUIRED`로 토큰이 지워질 때')에 없다. 헤더만 바뀌고 보고 있는 화면은 그대로라 오히려 어긋난다.

## 고려했지만 고르지 않은 것

- 헤더가 렌더링할 때마다 `getAccessToken()`을 읽기: 이동 없이 토큰만 바뀌면 헤더가 바뀌지 않는다(되돌려서 테스트 실패 확인).
- 로그인 상태 Context: 토큰을 바꾸는 곳이 모두 Provider 안의 컴포넌트가 아니다(API 클라이언트).
- 로그아웃을 `replace`로: 뒤로가기 동작이 달라지는 것 말고 얻는 것이 없다.

## 적용과 남은 점

- 다른 탭의 로그인·로그아웃을 반영해야 하면 사람이 정한다(정책: 사용자가 겪는 동작).
