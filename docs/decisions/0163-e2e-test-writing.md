# 0163. E2E 테스트 작성: 공연·좌석은 API로 찾고 화면에서는 목록 위치로 고른다. 로그인은 화면으로, 다른 사용자의 선점은 API로 만들고, 요소는 화면 영역으로 좁힌다

- 상태: 에이전트 결정
- 날짜: 2026-11-28
- 결정한 사람: 에이전트(Issue #59 '에이전트가 정하는 것': 공통 도우미, 테스트 방법)
- 관련: Issue [#59](https://github.com/Rasit-NP/curtain-call/issues/59), 결정 [0160](0160-e2e-reset-impl.md), [0162](0162-e2e-setup-impl.md), spec 2.5, 6.9, 7장

## 결정

- **파일**: 시나리오마다 spec 파일 하나(`tests/booking.spec.ts` 1, `seat-conflict.spec.ts` 2·R1, `seat-limit.spec.ts` 3·R2, `auth-guard.spec.ts` 4·R6),
  공통 도우미는 `tests/support/`(`accounts.ts` E2E 계정, `api.ts` 초기화·공연 찾기·다른 사용자의 선점, `ui.ts` 로그인·좌석 버튼·화면 영역).
- **초기화**: spec 파일마다 `test.beforeEach`에서 `resetData`(204 확인)를 부른다. 도우미 모듈 안에서 `beforeEach`를 등록하지 않는다.
  모듈은 한 번만 읽히므로, 그 모듈을 처음 가져온 파일에만 걸린다.
- **공연·좌석 찾기**: 공연 목록·상세 API로 빈 좌석이 n석 이상인 첫 공연과 그 빈 좌석들(좌석 순서)을 찾는다. id·제목·좌석 수를 가정하지 않는다(spec 2.5, 6.9).
  시나리오 1은 공연 목록 화면에서 그 공연의 위치(API 순서와 같다, spec 7.7)로 링크를 누르고, 주소의 id와 좌석 화면의 공연 제목으로 맞게 갔는지 확인한다.
  다른 시나리오는 좌석 화면 주소로 바로 들어간다.
- **로그인**: 화면에서 한다(아이디·비밀번호 입력, '로그인' 버튼). 헤더가 '로그아웃'으로 바뀔 때까지 기다린다. 토큰을 `localStorage`에 직접 넣지 않는다.
- **다른 사용자**: `request` 픽스처로 로그인 API → 선점 API(e2e-user2). 브라우저를 하나 더 띄우지 않는다(e2e/CLAUDE.md).
- **요소 찾기**: `getByRole`·`getByLabel`. 좌석 버튼은 접근성 이름 `{표시 이름} {상태}`(spec 7.2)로 찾는다.
  헤더와 이름이 겹치는 요소('내 예매' 링크)는 화면 영역(`section`의 `aria-labelledby`로 이름이 붙은 region, 이름은 화면 제목)으로 좁힌다.
  기대 문구는 명세 7.6의 문구를 그대로 쓴다. 고정 대기 없이 `expect`의 자동 재시도를 쓴다.
- **시나리오 2(R1)**: 잡힐 좌석과 빈 좌석 하나를 함께 골라, 안내 문구·결제 화면으로 넘어가지 않음·그 좌석 '선택 불가'에 더해
  함께 고른 좌석이 '선택 가능'으로 남고 API에서도 AVAILABLE인지 본다(묶음은 전부 잡히거나 하나도 잡히지 않는다, spec 1).
- **시나리오 4(R6)**: 로그인 화면으로 간 뒤 로그인하면 그 좌석 화면으로 돌아오는 것까지 본다(spec 7.1).

## 근거

- 시드 공연 중 제목이 같은 회차가 있어(시드 값은 샘플이라 바뀔 수 있다) 제목으로는 화면에서 공연을 고를 수 없다. 화면은 API 순서대로 그리므로 위치가 API와 맞는다.
  일시 문구로 고르면 E2E가 일시 표시 형식을 다시 구현해야 한다.
- 화면 로그인: 시나리오 1이 '로그인'부터 시작하고, 토큰을 직접 넣으면 프론트엔드의 저장 방식(키 이름)에 E2E가 기대게 된다. 로그인은 1초 안팎이라 느리지 않다.
- 화면 영역: 헤더에도 '내 예매' 링크가 있어 이름만으로는 두 요소에 걸린다(Playwright의 엄격 모드 오류). 화면 제목은 명세 7장이 정한 이름이다.
- 시나리오 2에 빈 좌석을 함께 고르는 이유: 한 좌석만 고르면 '묶음이 하나도 잡히지 않음'을 보지 못한다.

## 고려했지만 고르지 않은 것

- 자동 픽스처(`test.extend`의 `auto`)로 초기화: e2e/CLAUDE.md와 Issue가 `beforeEach`로 정했다.
- API로 받은 토큰을 `localStorage`에 넣어 로그인 건너뛰기: 위 근거.
- 브라우저 콘솔 오류가 있으면 실패: 4xx 응답(시나리오 2의 409)도 Chromium이 콘솔 오류로 남겨 걸러야 한다. 이번에는 넣지 않았다.

## 적용과 남은 점

- 코드: `e2e/tests/`.
- R1·R2·R6 시나리오를 구현의 해당 부분을 잠시 되돌려 실패하는지 확인했다(`docs/history/0059-e2e-setup.md` '규칙 시나리오 되돌림 확인').
